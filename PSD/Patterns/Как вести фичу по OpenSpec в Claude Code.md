## Как вести фичу по OpenSpec в Claude Code

### Подготовка: один раз

**В каждом новом чате нужна программа `openspec`.** Каждый новый чат в Claude Code on the web запускается в чистом облачном контейнере. Команды `/opsx:*` сами вызывают программу `openspec`, а в новом контейнере её нет. Сейчас в начале каждого чата нужно одно сообщение:

> Установи OpenSpec: `npm install -g @fission-ai/openspec@latest`, телеметрию отключи.

Могу добавить в репозиторий SessionStart-хук, который ставит её автоматически. Тогда этот пункт отпадёт — скажи, если нужно.

### Шаг 1. Новый чат

1. Открой claude.ai/code и выбери репозиторий `ekulaev/piaono_app`.
2. Claude сам создаст ветку под чат и прочитает `CLAUDE.md`. Все правила проекта (дизайн, слои, PR по-русски, OpenSpec) действуют автоматически, повторять их не нужно.

### Шаг 2 (по желанию). Обсудить требования: `/opsx:explore`

Этот шаг нужен, если требования сырые или ты сомневаешься в объёме.

/opsx:explore <вставь бизнес-требования>

- Claude разбирает требования вместе с тобой: ищет неоднозначности, противоречия с CLAUDE.md и уже готовыми спеками, предлагает варианты.
- Файлы на этом шаге не создаются — это просто разговор.
- Когда ясно, что делаем, переходи к шагу 3 в этом же чате.

### Шаг 3. Создать спецификацию: `/opsx:propose`

/opsx:propose <имя-фичи-через-дефисы>

<бизнес-требования>

Если требований много, можно положить их файлом в репозиторий (например, `docs/requirements/этап-2.md`This session isn’t running, so its files can’t be opened. Send a message to start it again.) и написать: «требования в docs/requirements/этап-2.md».

**Что сделает Claude:**

- задаст вопросы только по существенным неоднозначностям, мелочи запишет как допущения;
- создаст `openspec/changes/<имя>/` с четырьмя файлами: `proposal.md`, `specs/…/spec.md`, `design.md`, `tasks.md`;
- проверит их командой `openspec validate`;
- остановится: код на этом шаге он писать не будет.

**Твоё действие:** напиши «закоммить и открой PR со спекой».

### Шаг 4. Ревью спеки

Читай в таком порядке:

|Файл|Что проверить|
|---|---|
|`proposal.md`|Правильно ли понята цель? Нет ли лишнего в объёме, не забыто ли нужное?|
|`specs/*/spec.md`|Сценарии «КОГДА → ТОГДА» — это твои критерии приёмки. Каждый можно проверить руками на планшете? Тексты для ученика понятные?|
|`design.md`|Технические решения и новые зависимости: согласен ли с выбором?|
|`tasks.md`|Шаги маленькие, у каждого есть способ проверки?|

**Правки** пиши в чат обычными словами, например: «в сценарии X поменяй текст на Y», «убери требование Z — это следующий этап». Для правок, затрагивающих несколько файлов, есть `/opsx:update`: он держит proposal, спеки, design и tasks согласованными между собой.

Комментарии в PR на GitHub Claude сам не увидит. Либо пиши в чат, либо попроси его следить за PR.

**Когда всё устраивает, мержи PR** — это и есть «спека согласована».

### Шаг 5. Реализация: `/opsx:apply` (в новом чате)

Новый чат нужен, чтобы у Claude был чистый контекст и новая ветка.

/opsx:apply <имя-фичи>

- Claude идёт по `tasks.md` по порядку, после каждой задачи проверяет результат и ставит галочку `[x]` прямо в файле.
- Если прервёшься, в новом чате та же команда продолжит с первой неотмеченной задачи: прогресс хранится в `tasks.md`, а не в памяти чата.
- Если по ходу окажется, что спека не сходится с реальностью, Claude должен остановиться и предложить правку спеки, а не молча сделать по-своему. Если заметишь такое отклонение сам — попроси «обнови спеку».
- В конце: «закоммить и открой PR». В описании PR будет чек-лист проверки на планшете.

### Шаг 6. Проверка на планшете

1. Посмотри PR и замержи его. GitHub Actions задеплоит сайт на Pages примерно за минуту.
2. Пройди чек-лист из описания PR на планшете с пианино.
3. Если нашёл проблему — опиши её в том же чате, Claude исправит и откроет новый PR.

### Шаг 7. Закрыть фичу: `/opsx:archive`

Делай это после того, как проверка на планшете прошла успешно.

/opsx:archive <имя-фичи>

- Требования из фичи переносятся в `openspec/specs/` — это постоянное описание того, как приложение работает сейчас.
- Папка фичи переезжает в `openspec/changes/archive/<дата>-<имя>/` — это история.
- Дальше: «закоммить и открой PR» → мерж.

### Шпаргалка

|#|Чат|Команда|Результат|Твоё действие|
|---|---|---|---|---|
|0|новый|«установи OpenSpec»|CLI готов|—|
|1|тот же|`/opsx:explore` (по желанию)|требования прояснены|обсуждаешь|
|2|тот же|`/opsx:propose имя` + требования|4 файла спеки|«открой PR»|
|3|тот же|правки / `/opsx:update`|спека согласована|мерж PR|
|4|**новый**|`/opsx:apply имя`|код + галочки в tasks|«открой PR» → мерж|
|5|—|—|деплой на Pages|проверка на планшете|
|6|тот же|`/opsx:archive имя`|спеки в `openspec/specs/`|«открой PR» → мерж|

**Правила, чтобы не запутаться:**

- В работе одна фича за раз; одна фича — один пункт плана из CLAUDE.md.
- Код руками не меняй в обход спеки: сначала правка спеки, потом код.
- Если интересно, что уже описано: попроси «покажи `openspec list`» (фичи в работе) или «покажи `openspec list --specs`» (готовые спеки).
