# midi-input Specification

## Purpose

Приём нот с MIDI-входа: какой вход слушать, какие события отдавать наружу и как вести себя при
пропаже, смене и возвращении входа. Источник требований — C-MIDI-1 «MIDI-модуль и индикатор
связи», редакция 2; ссылки на его OB указаны в скобках.

## Requirements

### Requirement: Один активный вход
Приложение MUST принимать ноты только с одного входа — активного. Если подключён один вход,
он MUST быть активным. Если входов несколько, активным MUST быть предпочтённый вход (выбранный
учеником), если он подключён, иначе первый вход в порядке, в котором их перечисляет браузер.
Ноты с остальных входов MUST NOT приниматься. (OB-1, OB-2, INV-1)

#### Scenario: Один вход
- **WHEN** подключено одно пианино
- **THEN** его ноты принимаются без какого-либо выбора

#### Scenario: Два входа без выбора
- **WHEN** подключены входы «Piano» и «Synth» (в этом порядке), выбор ещё не делался
- **THEN** активен «Piano», нота с «Synth» не приходит в приложение

#### Scenario: Два входа с выбором
- **WHEN** ученик раньше выбрал «Synth», и подключены «Piano» и «Synth»
- **THEN** активен «Synth»

### Requirement: Выбор запоминается и узнаёт вход после переподключения
Выбор входа MUST сохраняться между запусками приложения. Предпочтённый вход MUST узнаваться
по идентификатору, а если вход с таким идентификатором не подключён — по имени. (OB-3, OB-4)

#### Scenario: Перезапуск
- **WHEN** ученик выбрал «Synth» и перезапустил приложение
- **THEN** активен «Synth»

#### Scenario: Новый идентификатор после переподключения
- **WHEN** выбранный вход «Synth» переподключили, и браузер выдал ему новый идентификатор
- **THEN** активен «Synth»

### Requirement: Пропажа активного входа при оставшихся других
Если активный вход отключился, а другие входы остались, активным MUST стать первый из
оставшихся. Предпочтение ученика MUST NOT стираться: когда предпочтённый вход снова
подключится, активным MUST снова стать он. (OB-5)

#### Scenario: Выбранный вход выдернули
- **WHEN** активен выбранный «Synth», и его отключили, а «Piano» остался
- **THEN** активен «Piano», состояние связи — «пианино на связи»

#### Scenario: Выбранный вход вернулся
- **WHEN** после предыдущего сценария «Synth» снова подключили
- **THEN** активен «Synth»

### Requirement: События нажатия и отпускания
Для активного входа note-on с velocity больше 0 MUST передаваться наружу как нажатие
`{ pitch, velocity, time }` на любом MIDI-канале. Note-off и note-on с velocity 0 MUST
передаваться как отпускание `{ pitch, time }`. Наружу MUST уходить только эти события и
изменения связи; сырые объекты Web MIDI MUST NOT выходить за пределы слоя `midi/`. Событие
MUST передаваться в том же обработчике сообщения, без таймеров и очередей. (OB-6, OB-7, OB-10,
NFR-1)

#### Scenario: Нажатие и отпускание
- **WHEN** активный вход передаёт `90 3C 64`, затем `80 3C 00`
- **THEN** наружу уходят нажатие C4 (60) с силой 100 и отпускание C4

#### Scenario: Отпускание через velocity 0
- **WHEN** активный вход передаёт `90 3C 00`
- **THEN** наружу уходит отпускание C4

#### Scenario: Другой канал
- **WHEN** активный вход передаёт note-on на канале 10 (`99 24 50`)
- **THEN** наружу уходит нажатие ноты 36

### Requirement: Неожиданные сообщения не ломают приём
Сообщения, не являющиеся note-on или note-off (control change, pitch bend, program change,
aftertouch, sysex, active sensing, clock), и обрезанные сообщения MUST игнорироваться. Ошибка
в обработчике события MUST NOT останавливать приём следующих сообщений. (OB-8, INV-2)

#### Scenario: Педаль и служебные сообщения
- **WHEN** активный вход передаёт `B0 40 7F`, `FE`, `F8` и `F0 7E 7F F7`
- **THEN** наружу ничего не уходит, следующий note-on принимается

#### Scenario: Обрезанное сообщение
- **WHEN** активный вход передаёт один байт `90`
- **THEN** наружу ничего не уходит, приложение продолжает работать

#### Scenario: Ошибка в обработчике
- **WHEN** обработчик нажатия бросил исключение
- **THEN** следующее сообщение с входа обрабатывается как обычно

### Requirement: Зажатые ноты отпускаются при смене входа
Когда вход перестаёт быть активным — отключился, ученик выбрал другой вход, связь потеряна —
для каждой ноты, нажатой на этом входе и ещё не отпущенной, MUST передаваться отпускание.
(OB-9)

#### Scenario: Кабель выдернули с зажатой клавишей
- **WHEN** на пианино зажата C4, и кабель отключили
- **THEN** наружу уходит отпускание C4, клавиша на экране не остаётся нажатой

#### Scenario: Смена входа с зажатой клавишей
- **WHEN** на «Piano» зажата E4, и ученик выбрал «Synth»
- **THEN** наружу уходит отпускание E4

### Requirement: Восстановление связи после сна
Список входов MUST пересматриваться при каждом изменении состояния MIDI-устройств. Когда
приложение снова становится видимым или снова получает фокус, модуль MUST переоткрывать
активный вход: закрыть его и открыть заново (программный аналог «выдернуть и вставить кабель»),
отпустив зажатые на нём ноты, затем пересмотреть список входов. Два сигнала возврата подряд MUST
давать одно переоткрытие. При каждой подписке на вход модуль MUST явно открывать его; отказ
открытия или закрытия MUST NOT останавливать работу модуля. (OB-11, OB-12)

#### Scenario: Сон и пробуждение
- **WHEN** планшет уснул с подключённым пианино и проснулся
- **THEN** ноты снова принимаются без действий ученика

#### Scenario: Вход не открылся
- **WHEN** явное открытие входа завершилось ошибкой
- **THEN** модуль продолжает работать, состояние связи отражает фактический список входов

#### Scenario: Вход перехватило другое приложение
- **WHEN** ученик переключился в другое приложение, которое заняло пианино, и вернулся
- **THEN** вход закрыт и открыт заново, ноты снова принимаются без переподключения кабеля

### Requirement: Ошибка доступа при разрешённом MIDI
Если запрос доступа к MIDI отклонён, модуль MUST сообщать состояние «доступ запрещён» только при
настоящем отказе: ошибка SecurityError или NotAllowedError и разрешение сайта на MIDI не
«granted» (или его нельзя узнать). Любая другая ошибка, а также отказ при разрешении «granted»,
MUST давать состояние «пианино занято». В этом состоянии модуль MUST тихо (без «подключаемся»)
повторять запрос каждые 5 секунд, пока доступ не будет получен. Текст ошибки («имя: сообщение»)
MUST передаваться наружу для диагностики и сбрасываться при успешном доступе.

#### Scenario: Пианино держит другое приложение
- **WHEN** MIDI разрешён, а запрос доступа отклонён, потому что пианино занято
- **THEN** состояние «пианино занято», не «доступ запрещён»; когда пианино освободили, через несколько секунд — «пианино на связи»

#### Scenario: Настоящий отказ
- **WHEN** пользователь запретил MIDI для сайта
- **THEN** состояние «доступ запрещён»

### Requirement: Ручное переподключение
Экран «Проверка пианино» MUST показывать кнопку «Переподключить пианино» (≥ 56×56 px) с
пояснением простыми словами во всех состояниях, кроме «браузер не умеет MIDI», и под ней — текст
последней ошибки запроса доступа, если она была. Нажатие MUST перезапускать приложение
(перезагрузка страницы): Chrome запускает MIDI один раз на страницу, повторный запрос без
перезагрузки получает прежний отказ.

#### Scenario: Переподключить вручную
- **WHEN** ноты не приходят, и ученик нажал «Переподключить пианино»
- **THEN** приложение перезапускается и заново запрашивает доступ к MIDI
