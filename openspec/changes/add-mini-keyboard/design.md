# Design

## Context

Мотивация — proposal.md, раздел Why. Требования — `specs/mini-keyboard` и изменение `piano-keyboard`.

Что из существующего переиспользуется:

- **`engine/keyboard/layout.ts`.** Чистая геометрия клавиатуры: `WHITE_PITCHES` (52 белые), `WHITE_KEY_COUNT`, `visibleRange`, `shiftStart`, `isBlocked`, приватный `clampStart`. Видимая часть задаётся индексом первой видимой белой клавиши `start` и числом видимых белых `count`.
- **`ui/keyboard/Keyboard.tsx`.** Держит `visible = { start, count }` как локальный стейт (в хранилище не пишется), рисует клавиши из этого окна, шаг прокрутки — `shiftStart` (одна белая клавиша). Кнопки прокрутки — по краям зоны, шириной в белую клавишу; сами клавиши смещены внутрь на ширину кнопки.
- **`ui/WaitingScreen.css`.** Сетка `[рабочая область 1fr][зона клавиатуры max(25svh, 8rem)]`; клавиатура — только на главном экране.

Мешает одно: `visible` живёт внутри `Keyboard`, а мини-клавиатуре нужно и читать это окно, и задавать его.

## Goals / Non-Goals

**Goals:**

- Одна модель видимой части `{ start, count }` — единственный источник правды и для клавиш, и для курсора; курсор всегда выводится из неё (INV-2 держится по построению).
- Вся геометрия мини и курсора — чистые функции в `engine/keyboard/layout.ts`, покрытые тестами; отрисовка и жесты — в `ui/keyboard/`.
- Отклик на жест — в том же кадре, без анимаций (как у клавиш).

**Non-Goals:**

- Субклавишная (плавная) прокрутка основной клавиатуры — шаг остаётся дискретным (C-KBD-2, Р-1).
- Новое хранилище: положение видимой части не сохраняется и сейчас — мини это не меняет.
- Отображение нажатых нот и зум-жесты на мини (C-KBD-2, «Вне Scope»).

## Decisions

### D1. Мини и зона клавиатуры — один вертикальный стек внутри `Keyboard`

`Keyboard` рендерит обёртку из двух частей: сверху — мини-клавиатура, снизу — существующая зона `.kbd`. Обе читают один и тот же `visible`; отдельного стейта у мини нет, в `App`/хранилище ничего не поднимается.

- Зона `.kbd` сохраняет свою высоту `max(25svh, 8rem)` — высота основной клавиатуры не меняется (OB-1).
- Строка сетки главного экрана под клавиатуру становится по содержимому (`min-content`), а не фиксированной: суммарная высота = мини + зона. Рабочая область (`1fr`) уменьшается на высоту мини — стан получает меньше высоты (C-KBD-2, Р-4).
- Альтернатива (мини как отдельный компонент в `WaitingScreen` с поднятием `visible` в `App`) отклонена: `visible` — внутреннее дело клавиатуры, поднимать его в `App` ради соседнего элемента усложняет поток данных без выгоды.

### D2. Геометрия мини и курсора — чистые функции в `layout.ts`

Мини раскладывает все 52 белые клавиши равномерно по полной ширине зоны (вместе с шириной кнопок прокрутки, OB-1): ширина белой на мини `wMini = zoneWidthPx / 52`. Чёрные рисуются поверх между белыми, как на основной клавиатуре (пропорции могут отличаться, OB-2 это разрешает). Курсор охватывает белые с индексами `[start, start + count - 1]`: левый край `start * wMini`, ширина `count * wMini`.

Новые функции (имена уточняются в реализации):

- `miniWhiteWidth(zoneWidthPx)` → `wMini`.
- `cursorRect(start, count, zoneWidthPx)` → `{ leftPx, widthPx }`.
- `startFromTapCenter(xPx, count, zoneWidthPx)` — целевой `start` так, чтобы центр курсора попал в точку тапа: `clampStart(round(xPx / wMini) - floor(count / 2), count)`.
- `startFromDrag(xPx, grabOffsetWhite, count, zoneWidthPx)` — при перетаскивании сохраняем белую клавишу курсора под пальцем: `clampStart(round(xPx / wMini) - grabOffsetWhite, count)`.

Все — через существующий `clampStart`, поэтому курсор не выходит за края и упирается в них (INV-1, OB-5, OB-8). Реюз `WHITE_PITCHES`, `WHITE_KEY_COUNT`, `isBlackKey`.

### D3. Дискретность и INV-2

Жест вычисляет целевой `start` (округление к белой клавише, клемпинг) и вызывает `setVisible`. Курсор перерисовывается из нового `start`/`count` — курсор и видимая часть не расходятся ни в одном кадре (INV-2), без анимаций. Шаг на мини ≈ `wMini` (20–25px на планшете) — перетаскивание ощущается почти плавным (C-KBD-2, В-1).

### D4. Жесты на мини

- `pointerdown` внутри прямоугольника курсора → перетаскивание: запоминаем, за какую белую клавишу курсора взялись (`grabOffsetWhite`), `setPointerCapture`, дальше по `startFromDrag`.
- `pointerdown` по затемнённой области → тап: сразу `startFromTapCenter`, без запуска перетаскивания (OB-6, OB-7).
- `touch-action: none` и `overscroll-behavior: none` на мини — как у `.kbd`, чтобы браузер не забирал жест.
- Мини не вызывает `onInput` движка — клавиши мини не играют (OB-11).
- Когда видны все 88 клавиш (`count === 52`, кнопок прокрутки нет): курсор во всю ширину, затемнения нет, жесты — no-op (OB-10).

### D5. Оформление курсора

Затемнённая область — полупрозрачный тёмный оверлей поверх мини (конкретная непрозрачность — на усмотрение отрисовки); курсор — «окно» без оверлея с контрастной рамкой ≥ 7:1. Акцентный цвет не используется (OB-3, C-KBD-2 Р-2). Цвета — из переменных `src/index.css`, новых оттенков без нужды не заводим.

## Risks / Trade-offs

- Мини отъедает у нотного стана свою высоту (`max(3.5rem, 10% высоты клавиатуры)`). → На планшете владельца это подтверждено (C-KBD-2, В-2); на очень низком экране (телефон в ландшафте) стан теряет заметную долю — проверить на 740×360; при необходимости высоту мини скорректировать отдельным решением, а не в этом change.
- Дискретный шаг мог бы читаться как «прыжок» курсора. → Шаг ≈ 20–25px, почти незаметен; согласовано (В-1).
- Мини проходит над кнопками прокрутки (OB-1). → Мини — отдельный элемент над зоной в своей строке, его указательные события не доходят до кнопок; конфликта нет.

## Migration Plan

Хранилище и форматы данных не меняются: положение видимой части не сохранялось и не сохраняется, ключи `piaono.settings.v1` / `piaono.progress.v1` не затрагиваются. Откат — обычным возвратом коммита; накопленные настройки и прогресс владельца не зависят от мини-клавиатуры.
