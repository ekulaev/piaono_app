# Design

## Context

Мотивация — proposal.md → Why. Требования — `specs/sequences-mode`; меню и сохранение настроек —
`mode-menu` из `add-mode-menu`.

Сейчас:

- **`engine/modes`.** `MODES = [warmup]`. Автомат меню без черновика настроек: у «Разминки» их
  нет. `Settings.activeMode` хранится.
- **`engine/staff`.** Автомат «Разминки» с временем в параметре, `tick` по кадрам, группа
  одновременных нажатий 50 мс.
- **`ui/staff`.** VexFlow в два SVG-слоя, движение через `transform`, кольца верной/неверной ноты
  рисуются через контекст VexFlow, цвета — токены `--note-correct` / `--note-wrong`.
- **`App`.** Держит `useExercise` («Разминка»), активный режим, меню. `playedNote` из движка
  клавиатуры идёт в упражнение.
- **`WaitingScreen`.** Строка кнопок: «Проверка пианино», «Старт/Стоп», «Режим: …». Стан —
  ReactNode в сетке.
- **`Keyboard`.** Сам держит видимую часть (`start`), центрирует C4 только при первом измерении.

## Goals / Non-Goals

**Goals:**

- Вся логика сессии (генерация, группы, верно/мимо/пропуск, отсчёт, итог) — чистые функции
  с временем в параметре и юнит-тестами по сценариям спеки.
- Режим встаёт в меню одной записью; «Разминка» не меняется.
- Отклик ≤ 50 мс: смена шага — одна отрисовка статичного SVG.

**Non-Goals:**

- Адаптивный подбор нот, хранение статистики между сессиями, «что улучшилось» (этап 6).
- Подсказки интервалов (этап 5).

## Decisions

### D1. `engine/sequences/generate.ts`

- `RANGES[range][clef] → { low, high }` — таблица из спеки.
- `buildSequence(settings, random)`:
  - ключ (для «Оба» — `random() < 0.5`);
  - длина `3 + floor(random() * 6)`;
  - каждый шаг — `notesPerStep` разных белых клавиш из диапазона (перемешивание кандидатов,
    берутся первые N, затем сортировка по высоте).
- `buildSession(settings, random)` → массив последовательностей. «Повторить» переиспользует тот
  же массив, поэтому его хранит состояние сессии.

### D2. `engine/sequences/session.ts` — автомат сессии

```
 idle --start--> playing(seq i, step j) --played/skip--> ... --last step--> finished(seq i)
                     ^                                                         |
                     +--------------------- next / countdown ------------------+
                                                                               |
                                                    last sequence: next ---> summary
```

- Состояние `playing` содержит:
  - `sequences` и индексы `seqIndex` / `stepIndex`;
  - `results[]` по шагам: `correct | error | skipped | pending`, `firstTry`, `reactionMs`;
  - `stepStartedAt`;
  - `group { startedAt, pitches:Set }`;
  - `wrongPitches` — полые головки;
  - `errorCount` — перезапускает пульсацию.
- Состояние `finished` добавляет `countdownUntil | null`.
- `played(state, pitch, now)`:
  - закрыть истёкшую группу;
  - если pitch не в шаге — ошибка сразу. Спека говорит «группа содержит лишнюю ноту», поэтому
    это ошибка без ожидания конца группы. `wrongPitches` — все неверные ноты текущей группы,
    новая ошибка заменяет прежние;
  - иначе добавить в группу; если группа содержит все ноты шага — верно сразу (для шага из одной
    ноты это первое же нажатие).
- `tick(state, now)`:
  - группа истекла, собрана только часть нот, лишних не было → ошибка без полых головок;
  - `countdownUntil` прошёл → `next`.
- `skip`, `next`, `stop` — переходы по спеке.
- `summarize(state)` → итог: подсчёты, точность, медленные ноты (среднее по высоте, до 5,
  по убыванию).

Время реакции — от `stepStartedAt` до верного нажатия. Шаг, ставший текущим после «Далее»,
получает `stepStartedAt` = момент перехода.

**Альтернатива:** объединить с автоматом «Разминки». Отклонена: у режимов разные фазы и
правила, общим остаётся только окно группы — константа `GROUP_MS` импортируется из
`engine/staff`.

### D3. Настройки режима и меню

- `engine/sequences/settings.ts`:
  - `SequenceSettings { clef: 'treble'|'bass'|'both'; range: 'position'|'octave'|'staff';
    sequences: 1..10; notesPerStep: 1..3; autoAdvance: boolean }`;
  - `DEFAULT_SEQUENCE_SETTINGS`;
  - `readSequenceSettings(unknown)` — проверка и значения по умолчанию.
- `MODES = [sequences, warmup]`: `sequences.hasSettings = true`.
- Автомат меню получает черновик: `{ screen: 'mode'; modeId; draft }`.
  - `chooseMode(state, id, confirmed)` кладёт копию подтверждённых настроек в черновик;
  - `editDraft(state, draft)`;
  - `confirm` возвращает `{ activeMode, settings }`;
  - «Назад» и закрытие черновик отбрасывают.

  Для «Разминки» черновик — `null`.
- `Settings.modeSettings = { sequences: SequenceSettings }` в том же ключе `piaono.settings.v1`.
  Битые или отсутствующие данные дают значения по умолчанию.

### D4. Элементы настроек — `ui/controls/`

- `ChoiceGroup` — ряд кнопок `role="radiogroup"`, выбранная залита `--ink` с меткой «✓». Метка —
  это текстовый символ, а не эмодзи-иконка; смысл передаёт заливка.
- `Stepper` — «−» / число / «+». Кнопки ≥ 3.5rem, `disabled` на границе, число ≥ 1.75rem.
- `Toggle` — кнопка-флажок `role="switch"` с квадратом и «✓», подпись рядом.

Всё — обычные `button`, без `input type="range/checkbox"`: единый стиль, крупные цели, нет
системного оформления (C-MODE-1 NFR-1). Ползунки из исходного C-STF-2 заменены счётчиками
(решение explore).

### D5. Отрисовка последовательности — `ui/sequences/SequenceStaff.tsx`

- Один SVG. Перерисовывается целиком при смене состояния сессии: движения нет, кадровый цикл
  не нужен.
- Сама отрисовка — `staffDrawing` («Разминка»): та же геометрия зоны, толстые линии, `Stave`
  с ключом.
- Шаги:
  - `StaveNote` с `keys` шага, длительность `q`, штиль скрыт;
  - расстановка — равномерно от ключа до правого края стана (`TickContext` вручную, как в
    «Разминке»); на 1280×800 промежуток при 8 шагах — не меньше двух ширин головки;
  - цвета через `setStyle`: текущий — `--note-current` (затемнённый акцент ≥ 7:1), верный —
    `--note-correct`, пропущенный — `--ink-soft`, остальные — `--ink`.
- Отметки рисуются контекстом VexFlow по `getBoundingBox()` шага:
  - верный — сплошной круг вокруг каждой головки;
  - пропущенный — сплошной квадрат вокруг шага;
  - текущий — толстая черта под станом.
- **Ошибка.**
  - Группа текущего шага оборачивается через `openGroup` в `seq-step`, а при ошибке — в
    `seq-step-pulse` (VexFlow добавляет приставку: в CSS это `.vf-seq-step-pulse`).
  - CSS `@keyframes` даёт две пульсации (`scale 1 → 1.15 → 1`, 0,8 с, `transform-box:
    fill-box`). Анимация стартует при создании SVG, поэтому одинаковый вид не
    перерисовывается (ключ отрисовки включает `errorCount`: новая ошибка — новая пульсация).
  - Пунктирная рамка рисуется всегда, но видна только при `prefers-reduced-motion: reduce`;
    при нём же анимация отключена.
- **Полые головки.** Ноты `w` (целые, полые) цвета `--note-wrong` в отдельном
  `TickContext`, x = x шага + 2 ширины головки.
- Размер: высота зоны вмещает диапазон «Весь стан» с двумя добавочными линиями, как в
  «Разминке». Ширина — 90 % зоны.

### D6. Экран итога — `ui/sequences/SessionSummary.tsx`

Рендерится вместо стана в той же зоне, без наложения:
- три числа крупно;
- точность;
- список медленных нот («C4 — 2,4 с»);
- «Повторить» и «Новая».

Текст ≥ 1.25rem, контраст токенов ≥ 7:1.

### D7. Встраивание

- `useSequenceSession()` в `ui/sequences/`:
  - состояние автомата и цикл `requestAnimationFrame` только пока есть открытая группа или
    отсчёт (для `tick`);
  - методы `start`, `stop`, `played`, `skip`, `next`, `repeat`.
- `App`:
  - `startMode('sequences')` — сессия из подтверждённых настроек;
  - сыгранные ноты идут в активное упражнение;
  - «Режим» и «Проверка пианино» останавливают оба упражнения и закрывают итог;
  - в зону стана — `StaffView`, `SequenceStaff` или `SessionSummary`.
- `WaitingScreen` получает `slotButton` (`{ label, onClick } | null`). Если он есть, кнопка
  «Проверка пианино» заменяется им («Пропустить» / «Далее (N)»). Число кнопок и высота ряда не
  меняются (INV-2).
- `Keyboard` получает `focus?: { low, high, token }`. При смене `token` видимая часть
  центрируется на середине диапазона через `layout` (новая чистая функция `centerStartOn`,
  с тестом). Меняется только положение, состояние клавиш не трогается.

### D8. Цвет текущего шага

Токен `--note-current: #145048` — затемнённый акцент, контраст 7,9:1 с «бумагой». Базовый
`--accent` (#1f6e63, 5,2:1) для нот не годится. Остальные элементы стана акцент не используют
(INV-1).

## Risks / Trade-offs

- **[Окно группы 50 мс для аккордов]** Живой аккорд берут с разбросом 20–60 мс, возможны ложные
  «неполный аккорд». → По умолчанию шаг из одной ноты. Окно — одна константа, её легко подобрать
  на планшете. Отмечено в чек-листе PR.
- **[Скрытие штиля в VexFlow 5]** → Используется публичный API стиля штиля (прозрачный). Если не
  выйдет, запасной путь: головки глифами `noteheadBlack` через `GlyphNote`.
- **[Телефон в ландшафте]** Стан уже мелкий (этап 3). 8 шагов там будут тесными. → Целевой
  экран — планшет, NFR-2 задан для 1280×800.
- **[Размер `App`]** Второе упражнение, итог и слот кнопки утяжеляют `App`. → Логика в хуках
  и `engine/`, `App` только связывает. Если станет трудно читать — вынести `MainScreen`.

## Migration Plan

Настройки совместимы: новые поля необязательные, при отсутствии — значения по умолчанию. Откат —
revert PR.
