# Design

## Context

Мотивация — proposal.md, раздел Why. Требования — `specs/interval-hints`, изменения
`specs/sequences-mode` и `specs/staff-exercise`.

Как устроено сейчас:

- **`engine/sequences/generate.ts`.** `buildSequence` берёт для каждого шага случайные разные
  белые клавиши диапазона (`pickDistinct`). У `Sequence` есть поля `clef`, `low`, `high`, `steps`.
- **`engine/sequences/session.ts`.** Чистый автомат `idle → playing → finished → summary`, время
  передаётся параметром. `StepRecord` хранит `result`, `hadError`, `reactionMs`. Ошибка отмечается
  в `played` (лишняя нота) и в `closeGroup` (неполный аккорд). «Повторить» переиспользует массив
  `sequences`.
- **`ui/staff/staffDrawing.ts`.** Геометрия: `VIRTUAL_HEIGHT = 2 × TOP_MARGIN + 4 × SPACING` (120
  условных единиц); `scale = высота зоны / VIRTUAL_HEIGHT`; `makeStave` ставит стан на
  `y = TOP_MARGIN`. Свободного места над станом нет: `TOP_MARGIN` вмещает ровно две добавочные
  линии.
- **`ui/sequences/sequenceDrawing.ts`.** Шаги стоят равномерно: `gap = доступная ширина / число
  шагов`, шаг i — на `gap × i`. Весь SVG перерисовывается при каждой смене состояния. Ключ
  отрисовки собирается в `SequenceStaff`.
- **`storage/settings.ts`.** Единственное место с `localStorage`. Ключ `piaono.settings.v1`,
  `modeSettings.sequences` читается через `readSequenceSettings`.
- **`App.tsx`.** Держит подтверждённые настройки режима и запускает `sequences.start(settings)`.

## Goals / Non-Goals

**Goals:**

- Вся логика подсказок — чистые функции в `engine/` с юнит-тестами по сценариям спеки: опорные
  ноты, интервалы, уровни, видимость, угасание.
- Смена видимости подсказки — та же одна перерисовка статичного SVG, что и сейчас. Отклик остаётся
  в пределах 50 мс.
- Геометрия стана и позиций фиксирована на всю сессию.

**Non-Goals:**

- Статистика по нотам и интервалам между сессиями (этап 6). Этот change сохраняет только уровни
  подсказок, но кладёт их в новый модуль `storage/progress.ts`, который этап 6 расширит.
- Подсказки для аккордов.

## Decisions

### D1. `engine/sequences/anchors.ts` — опорные ноты и интервалы

- `ANCHORS: Record<Clef, number[]>` — `{ treble: [60, 67, 72], bass: [48, 53, 60] }`.
- `anchorsIn(clef, low, high)` — опорные ноты внутри диапазона.
- Интервал считается по белым клавишам. Все ноты режима — белые клавиши, поэтому число ступеней
  стана равно разнице индексов в списке белых клавиш плюс 1:
  - `whiteIndex(pitch)`;
  - `intervalBetween(a, b)` → `{ size: 2..8, direction: 'up' | 'down' }`;
  - `moveBy(pitch, size, direction)`.
- `MAX_INTERVAL: Record<IntervalChoice, number>` — `{ third: 3, fifth: 5, octave: 8 }`.
- `widestFitting(range, choice)` — самый широкий допустимый интервал, помещающийся в диапазон. Меню
  по нему показывает строку «В этом диапазоне — не больше …». Число белых клавиш у скрипичного
  и басового диапазонов одинаковое: 5 / 8 / 13, поэтому ключ здесь не нужен.
- `INTERVAL_NAMES` — «секунды» … «октавы» для этой строки.

**Альтернатива:** считать интервал в полутонах. Отклонена: подсказка описывает расстояние на стане,
а не звучание. Полутоны дали бы разные числа для одинаковых на вид терций.

### D2. Генератор

- `Sequence` получает поле `anchor: number | null`; `null` — у шагов из нескольких нот.
- При `notesPerStep === 1`:
  - `anchor` — случайная из `anchorsIn`;
  - дальше каждый шаг — функция `nextByInterval(from, allowed, low, high, random)`: из допустимых
    размеров `2..MAX_INTERVAL` оставить те, у которых помещается хотя бы одно направление; выбрать
    размер равновероятно; затем выбрать направление равновероятно среди помещающихся.
- При `notesPerStep > 1` — прежний путь через `pickDistinct`.
- `settings.intervals` новое, значение по умолчанию `third`.

Равновероятный выбор размера, а не пары «размер + направление», сделан, чтобы у края диапазона
широкие интервалы не вытеснялись узкими.

### D3. `engine/sequences/hints.ts` — уровни и видимость

```
type HintLevel = 0 | 1 | 2 | 3
interface ClefProgress { level: HintLevel; streak: number }
type HintProgress = Record<Clef, ClefProgress>          // по умолчанию { 3, 0 } у обоих
interface HintVisibility { anchor: boolean; anchorLabel: boolean; steps: boolean[] }
```

- `initialVisibility(level, stepCount)` — таблица уровней из спеки.
- `revealStep(visibility, stepIndex)` — после ошибки: шаг, а для шага 0 ещё якорь и подпись.
- `classify(records)` → `'success' | 'hard' | 'other'`.
- `nextProgress(progress, clef, records)` — правила угасания и возврата.
- `readHintProgress(unknown)` — проверка сохранённых данных, как `readSequenceSettings`.

Схема для одного ключа:

```
   success x2                 success x2          success x2
 3 ----------> 2 -----------> 1 -----------> 0
 ^             ^ |            ^ |            |
 |   hard      | |   hard     | |   hard     |
 +-------------+ +------------+ +------------+
        (other: streak = 0, level unchanged)
```

### D4. Автомат сессии

- В `Common` добавляется поле `hints: HintProgress | null`. `null` — подсказки не действуют:
  выключены или `notesPerStep > 1`. Решение принимает `App` при старте.
- `playing` и `finished` получают поле `visibility: HintVisibility | null`. Его задаёт
  `playSequence` по уровню ключа последовательности.
- При ошибке, то есть в тех же местах, где ставится `hadError` (`played` и `closeGroup`), вызывается
  `revealStep`.
- В `StepRecord` добавляется поле `hinted: boolean` — была ли подсказка над шагом в момент верного
  нажатия.
- Переход в `finished` пересчитывает `hints` через `nextProgress`. `stop` сбрасывает сессию в `IDLE`
  без пересчёта: прерванная последовательность уровни не меняет.
- `summary` получает поле `hintsUsed: boolean`, а `summarize` — поле
  `withoutHint: { count, of } | null`.
- `startSession(sequences, autoAdvance, hints, now)`. `repeat` берёт текущий `state.hints`.

**Альтернатива:** держать уровни вне автомата, в `App`. Отклонена: правило «уровень меняется только
между последовательностями» пришлось бы повторять в UI, и тесты не видели бы его целиком.

### D5. Хранение уровней — `storage/progress.ts`

- Отдельный ключ `piaono.progress.v1`: прогресс — не настройки, у него своя версия формата.
  Этап 6 добавит сюда статистику.
- `loadHintProgress()` и `saveHintProgress(progress)`. Помощник `browserStorage` выносится из
  `settings.ts` и используется обоими модулями, чтобы доступ к `localStorage` остался в `storage/`.
- `App` передаёт `loadHintProgress()` в `start`. Когда `state.hints` меняется, сохраняет его
  эффектом по ссылке на объект: автомат создаёт новый объект только при пересчёте.

### D6. Геометрия с полосой подсказок

- `staffGeometry(zoneW, zoneH, hintBand = 0)`: виртуальная высота равна
  `hintBand + VIRTUAL_HEIGHT`. В `StaffGeometry` добавляется поле `staveY = hintBand + TOP_MARGIN`.
  `makeStave` берёт `y` из геометрии. `CURRENT_BAR_Y` считается от `staveY`.
- `HINT_BAND = 36` условных единиц: 36 / 156 ≈ 23 % зоны, это не больше четверти. Цифра — шрифт
  28 единиц, высота цифры ≈ 20 единиц, то есть два промежутка стана (NFR-1).
- «Разминка» вызывает `staffGeometry` без третьего аргумента, её вид не меняется (C-STF-3/INV-5).

### D7. Отрисовка якоря и подсказок — `sequenceDrawing.ts`

- `SequenceView` получает поля `anchor: number | null` и `visibility: HintVisibility | null`. Если
  `visibility !== null`, позиций `steps + 1`: позиция 0 — якорь, шаг i — на позиции i + 1. Позиции
  не зависят от того, что видно.
- Якорь — `StaveNote` длительности `w` (полая) цвета `--ink`. Рисуется, только если
  `visibility.anchor`.
- Подсказка интервала рисуется в полосе над позицией:
  - **цифра** — `context.fillText`, шрифт интерфейса, вес 600, `--ink`, по центру позиции
    (`measureText`);
  - **стрелка** — толстая линия и треугольный наконечник, нарисованные путём слева от цифры.
- Подпись якоря — текст, например «G4», над позицией 0.
- В ключ отрисовки в `SequenceStaff` добавляются `visibility` и `anchor`.

**Почему стрелка — путь, а не символ «↑»:** наличие и толщина символа зависят от шрифта устройства.
Путь всегда одной толщины и не пропадёт на Android. Цифры есть в любом шрифте.

### D8. Настройки и меню

- `SequenceSettings` получает поля `intervals: 'third' | 'fifth' | 'octave'` и `hints: boolean`,
  `readSequenceSettings` проверяет оба.
- `ChoiceGroup` и `Toggle` получают проп `disabled`. Оформление — как у `.button:disabled`:
  пунктир и приглушённый текст.
- `SequenceSettingsForm`:
  - «Интервалы» после «Диапазона»;
  - «Подсказки» после «Нот в шаге»;
  - строка «В этом диапазоне — не больше …» из `widestFitting`;
  - строка «Только для шагов из одной ноты» при `notesPerStep > 1`.
- Требования меню режимов не меняются: черновик и подтверждение уже работают для всего объекта
  настроек.

### D9. Итог

`SessionSummary` показывает строку «Без подсказки: N из M» («—» при M = 0), когда
`withoutHint !== null`.

## Risks / Trade-offs

- **[Стан меньше на ~23 %]** На телефоне в ландшафте стан и так мелкий. → Полоса только при
  действующих подсказках. Выключенные подсказки возвращают прежний размер. На планшете проверяется
  по чек-листу.
- **[Пороги угасания]** «2 успешные подряд» и «больше половины» — предположение без проверки на
  ученике (C-STF-3, вопрос В-1). → Пороги — две константы в `hints.ts`, калибруются после недели
  занятий отдельным маленьким PR.
- **[Шрифт цифры]** Высота цифры зависит от метрик шрифта интерфейса. → Проверяется
  headless-скриншотом: измерить высоту цифры в px против двух промежутков стана.
- **[`measureText` в SVG-контексте VexFlow]** Ширина текста может посчитаться до загрузки шрифта.
  → Отрисовка уже ждёт `useMusicFont`, шрифт интерфейса системный. Центрирование проверяется
  скриншотом.

## Migration Plan

- Настройки совместимы: новые поля необязательные, при отсутствии — значения по умолчанию.
- Прогресс хранится под новым ключом, при первом запуске уровни равны 3.
- Откат — revert PR. Ключ `piaono.progress.v1` старая версия не читает, и он ей не мешает.
