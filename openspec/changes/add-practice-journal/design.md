# Design

## Context

Статистика — `engine/stats/stats.ts`: режим копит `ModeStats` из событий `StatEvent` (вид места,
ключ, исход `clean` / `error` / `skip`, время). Дат нет нигде. Основная таблица режима для «Попыток»
на «Прогрессе» задана в `engine/stats/summary.ts` (`MODE_VIEW`).

Прогресс — `storage/progress.ts`: `readProgress` читает части `hints` и `stats` независимо, запись —
через `update()` (прочитать всё → заменить свою часть → записать). Резервная копия
(`storage/backup.ts`) берёт `loadProgress()` целиком и читает файл через тот же `readProgress`,
поэтому новая часть прогресса попадает в копию сама.

`ui/App.tsx`: `startMode()` — единственная точка запуска любого режима (кнопка «Старт», меню, итоги).
Статистика пишется в четырёх `useEffect`: «Последовательности» и «Контур», «Ритм», сольфеджио,
«Разминка». Каждый видит накопленный за сессию массив событий (`stats.events` / `results`) и
пишет `applyEvents(before, events)` после каждой законченной попытки. Прерванное в массив не
попадает (capability `practice-stats`).

«Прогресс» — `ui/progress/ProgressScreen.tsx`: `ChoiceGroup` по `MODES` и сводка выбранного режима.
Даты и числа — `i18n/format.ts`, формы числительных — `pluralForm` в `i18n/translate.ts`.

Требования — `specs/`; мотивация — proposal.md.

## Goals / Non-Goals

**Goals:**
- Вся логика журнала — чистые функции `engine/journal/` с тестами: время приходит параметром,
  `Date.now()` и часовой пояс вызывает только `ui/`.
- Журнал пишется в тех же местах и тем же способом, что статистика: одна точка правды о
  «законченной попытке», прерванное отсекается само.
- Формат хранения маленький и терпимый к повреждениям, без `.v2`.

**Non-Goals:**
- Запись на каждую сессию или каждую попытку с отметкой времени: не нужна ни одному требованию, а
  объём растёт с числом нажатий.
- Общий компонент «календарь»: нужен одному экрану.
- Тренд по неделям (`Б-STF-16`): журнал хранит для него данные, но расчёта и вида нет.

## Decisions

**Д-1. Формат журнала.** Новая часть `journal` в записи `piaono.progress.v1`:

```json
{
  "journal": {
    "2026-10-31": { "ms": 1500000, "modes": { "warmup": [48, 39], "intervals": [12, 12] } }
  }
}
```

Ключ — дата дня занятий `ГГГГ-ММ-ДД` с учётом границы 04:00; `ms` — время занятий в миллисекундах;
`modes` — режим → `[попыток, чисто]`. Пара вместо объекта `{attempts, clean}` держит день в пределах
200 байт и при шести режимах (около 150 байт); в коде пара разворачивается в именованный тип сразу
при чтении. Альтернатива — массив дней: ключ-дата проще ищется, не бывает двух записей одного дня.

**Д-2. Ключ дня.** `dayKey(local: {year, month, day, hour})` — чистая функция: если `hour < 4`, день
сдвигается на предыдущий (с переходом месяца и года). `ui/` передаёт местное время устройства из
`new Date()`. Дата хранится «настенной», без часового пояса — как дата резервной копии
(`C-APP-4`, Д-2): занятие в 23:00 по Москве остаётся тем же днём и после переезда в другой пояс.

**Д-3. Чтение.** `readJournal(value)`: не объект → пустой журнал; ключ не дата `ГГГГ-ММ-ДД` или
значение без целого неотрицательного `ms` → день отбрасывается; у режима не `StatsMode` или пара
не из двух целых `0 ≤ чисто ≤ попыток` → отбрасывается только этот режим. `readProgress` получает
третью часть: `{ hints, stats, journal }`. Старая запись без `journal` → пустой журнал.

**Д-4. Что записывать при событиях.** `journalEntry(mode, events)` → `{attempts, clean}`: события
основной таблицы режима (её определение переезжает из `summary.ts` в `stats.ts` как
`MAIN_KIND`, чтобы журнал и «Прогресс» считали «Попыток» одинаково). Событие «чисто» —
`outcome === 'clean'`. `recordAttempts(journal, day, mode, entry, gapMs)` возвращает новый журнал:
прибавляет попытки и `gapMs`, если он не больше 2 минут.

**Д-5. Отсчёт в `App.tsx`.** Ref `journalClock = { lastAt, logged }`:
- `startMode()` ставит `lastAt = Date.now()` и обнуляет `logged` (счётчики уже записанных событий
  сессии по режиму);
- в каждом из четырёх эффектов статистики берутся события после `logged`, `gap = now - lastAt`,
  журнал пишется `saveJournal(...)`, затем `lastAt = now`, `logged = events.length`.

Почему не по фазам автоматов: `startMode()` — уже единственная точка запуска, а события — уже
единственный признак законченной попытки. Пачка событий одной последовательности приходит одним
эффектом — это один промежуток, как и задумано (время до конца последовательности).

**Д-6. Хранение и состояние.** `saveJournal(journal)` в `storage/progress.ts` через `update()`;
запись статистики и журнала — два последовательных синхронных `update()`, каждый читает свежую
запись, поэтому они не стирают друг друга. `Main` держит `journal` в `useState` (как `practice`) и
передаёт в `ProgressScreen`.

**Д-7. Календарь и итоги — `engine/journal/calendar.ts`.** `calendarWeeks(today, offsetWeeks)` →
5 недель по 7 дат (понедельник — воскресенье), даты после `today` помечены как будущие;
`journalTotals(journal, today)` → `{ days, firstDay, weekDays, weekMs }`; `canGoEarlier`,
`canGoLater`. Всё на строках `ГГГГ-ММ-ДД` и целых днях через `Date.UTC`, без часового пояса.

**Д-8. Экран.** `ProgressScreen` — выбор `'journal' | ModeId`, подпись «Показать», по умолчанию
активный режим. Вид «Занятия» — новый компонент `ui/progress/JournalView.tsx`: слева календарь
(сетка 7 столбцов, клетка `button` ≥ 44px, `aria-pressed` у выбранной, `aria-label` с полной датой
и «занимался» / «не занимался»), справа числа и подробности; на узком экране — одна колонка, как у
остальных экранов через `clamp()`. Выбранный день и смещение недель — `useState` компонента.
Цвета — существующие переменные `src/index.css`: заливка дня — цвет нот (тёмный), рамки — цвет
границ кнопок; акцент «играть сейчас» не используется.

**Д-9. Форматы языка.** В `i18n/format.ts`: `formatDayTitle(code, day)` — «Четверг, 29 октября» /
«Thursday, 29 October»; `formatDuration(code, ms)` — «25 мин», «1 ч 20 мин» / «25 min», «1 h 20 min»;
меньше минуты — текст перевода «меньше минуты». Короткие дни недели — ключи перевода, а не
`Intl` (разные версии ICU пишут их по-разному, как с месяцами в `formatDate`). Дата «с …» —
«с 31 октября 2026» / «since 31 October 2026».

## Risks / Trade-offs

- [Часы планшета переведены назад] → день записывается в «прошлую» дату; журнал это принимает,
  ничего не ломается. Отдельной защиты не делаем.
- [Ученик думает дольше 2 минут над одной последовательностью] → это время не войдёт. Принято
  (C-STF-10, Р-12): лучше недосчитать, чем записать чай как занятие.
- [Две вкладки приложения одновременно] → последняя запись побеждает, как уже сейчас со
  статистикой. Не усложняем.
- [Восстановление старой копии стирает журнал] → так задумано (`C-APP-4`: копия заменяет всё);
  диалог восстановления уже показывает дату копии.
- [Объём] → около 150 байт на день, год ежедневных занятий ≈ 55 КБ: и `localStorage`, и предел
  копии 1 МБ выдерживают много лет.

## Migration Plan

Миграции нет: часть `journal` добавляется в `.v1`, старые записи читаются с пустым журналом.
Откат — предыдущая версия просто не читает поле `journal` и при следующей записи прогресса его
уберёт; статистика и подсказки не пострадают.
