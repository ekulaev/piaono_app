# Design

## Context

Ядро сольфеджио (`engine/solfege/`) уже многорежимное по модели данных: `Task.mode` — режим-источник, `Answer` — ответ-нота или ответ-значение по таблице «ступень от до → значение», `pickTypes` — взвешенный выбор типов без повтора подряд, `session.ts` — ход задания. Но **UI привязан к «Интервалам»** жёстко:

```
 ui/App.tsx
   startMode case 'intervals'   -> buildIntervalTasks(...)
   saveModeStats('intervals')   <- события сессии
   onNew -> startMode('intervals')
   SolfegeStaff -> intervalNotes()          (ui/solfege/intervalsView.ts)
   legendLabels = intervalLegend
   bounds = INTERVALS_RANGE, focus = intervalFocus(), marks = intervalKeyMarks()
 engine/stats/stats.ts
   TASK_KEY = isIntervalTaskType            (ключи таблицы tasks)
```

Стан задания (`ui/solfege/solfegeDrawing.ts`) рисует до трёх **целых** нот со знаками и отметками (кольцо, пунктир, рамка). Легенда клавиатуры (`Keyboard.tsx`, `Legend`) принимает `Record<ступень, string>` — только текст. Нотный шрифт Bravura зарегистрирован в документе при загрузке VexFlow (`ui/staff/staffHooks.ts`), его можно использовать в CSS.

## Goals / Non-Goals

**Goals:**
- Режим «Длительности» по `C-SOL-3` на готовом ядре.
- UI ядра выбирает содержание по `task.mode`, а не по константе «Интервалов»; поведение «Интервалов» не меняется.

**Non-Goals:**
- Реестр режимов «на вырост», смешанный режим (`Б-SOL-8`), точки (`Б-SOL-9`).
- Изменение ядра `engine/solfege/session.ts` и `pick.ts`.

## Decisions

**1. Вид режима — объект `SolfegeView` в `ui/solfege/`, выбор по `task.mode`.**
```
 ui/solfege/views.ts
   SOLFEGE_VIEWS: Record<SolfegeModeId, {
     staff(state)  -> что рисовать на стане
     marks(state)  -> отметки клавиш
     focus(task)   -> запрос сдвига или null
     legend        -> подписи легенды или null
     bounds        -> диапазон прокрутки или null
     prompt(state) -> строка над станом
   }>
```
`intervals` собирается из существующих функций `intervalsView.ts` без изменений; `durations` — новый `durationsView.ts`. `App.tsx` берёт вид из `SOLFEGE_VIEWS[task.mode]`, статистику сохраняет в `task.mode`, «Новая» запускает режим текущей сессии. Альтернатива — `if (mode === 'durations')` в каждом месте `App.tsx`: дешевле на один режим, но ветвится в шести местах и повторится на каждом следующем. Объект из шести полей — не «абстракция на вырост», а то, что уже нужно двум режимам.

**2. Содержание режима — `engine/solfege/durations/`.**
```
 durations.ts  DurationId 'w'|'h'|'q'|'8'|'16'; Kind 'note'|'rest'|'group';
               12 типов `${kind}:${duration}`, isDurationTaskType, пары
 keymap.ts     { 0:'w', 2:'h', 4:'q', 5:'8', 7:'16' }  (ля, си, чёрные — нет в таблице)
 generate.ts   типы по настройке -> веса ×2 у пар -> последовательность
               с правилом «следом пара ~50 %» -> buildTask (высоты C4..B5, группа 2..4)
 settings.ts   { kinds: 'notes'|'rests'|'both', tasks: 1..10, autoAdvance }
```
Правило пары: генератор идёт по шагам сам — после типа из пары с вероятностью 0,5 берёт тип пары (если он допустим настройкой), иначе — обычный взвешенный выбор без повтора подряд (`weightedPick` из `stats/weights.ts`). `pickTypes` ядра не меняется (`C-SOL-3` Р-20). Вес: `2 × weight(type)` для типов пар, где `weight` — готовый вес по трудности. Генератор берёт `random` параметром — тесты детерминированы.

`range` задания — легенда до–соль ближайшей октавы; авто-сдвига у режима нет (`focus` → `null`), `bounds` → `null`.

**3. Статистика.** `StatsMode` += `durations`, `readPracticeStats` читает `durations`. Проверка ключей таблицы `tasks` — `isIntervalTaskType(k) || isDurationTaskType(k)`: одна таблица и одна функция чтения, как сейчас; ключи режимов не пересекаются (`play:up:m3` против `rest:h`). Сводка: `MODE_VIEW.durations = { main: 'task', lists: [{ id: 'tasks', kind: 'task' }] }`; подпись типа — из переводов по режиму.

**4. Отрисовка знака.** `SolfegeNote` получает необязательные `duration` (по умолчанию `'w'` — «Интервалы» рисуются как раньше) и `rest`; новая функция рисует группу `SolfegeNote[]` под одним `Beam` VexFlow (по образцу `rhythmDrawing.ts`). Паузы ставятся с ключом `b/4` — VexFlow сам вешает целую под 4-й линией и кладёт половинную на 3-ю. Штиль — авто-направление VexFlow (`Stem.AUTO` по высоте). Отметки «верно / пропуск» — те же кольцо и рамка вокруг знака (у группы — рамка вокруг всей группы). Толщина штилей и рёбер — как у «Ритма».

**5. Легенда со значком.** Значение легенды: `string | { glyph: string; text: string }`. Значок — символ SMuFL нотного шрифта Bravura (целая U+E1D2, половинная U+E1D3, четвертная U+E1D5, восьмая U+E1D7, шестнадцатая U+E1D9) в `<span>` с `font-family: Bravura`, над дробью; размер — не мельче текста легенды. Строки легенды «Интервалов» остаются строками — их вид не меняется. Полоса легенды выше на строку значка только в «Длительностях»; высоту резервируем на всю сессию режима, чтобы стан не прыгал.

**6. Строка над станом.** «Какая длительность?» → «✗ 1/8» (красным) → «✓ Восьмая пауза» (зелёным) — та же зона фиксированной высоты, что у «Интервалов».

**7. Меню, настройки, подсказка, переводы.** `ModeId` += `durations`, шестым в `MODES`; `ModeSettings.durations` с чтением по образцу `intervals/settings.ts`; форма — `ChoiceGroup`, `Stepper`, `Toggle`. Подсказка `mode.durations` — абзац, таблица «Клавиша · Длительность», таблица октав. Переводы: `duration.name.*` (полные: «Целая нота», «Половинная пауза», «Восьмые под ребром»), `duration.fraction.*` не нужны — дроби одинаковы на всех языках и берутся из таблицы; `solfege.durations.*` (формулировка, приглашение, «Что тренировать»).

## Risks / Trade-offs

- **Обобщение `App.tsx` задевает «Интервалы».** → `intervals`-вид собирается из прежних функций без правок; тесты на `intervalsView` остаются; Playwright: «Интервалы» — легенда «м3», границы C4–C6, итог — как до change.
- **Значок Bravura в HTML может не загрузиться** до первой отрисовки стана. → Шрифт уже ждёт `staffHooks.ts` (`document.fonts.load`); легенда появляется после старта сессии, когда стан нарисован. Дробь видна в любом случае.
- **Высота полосы легенды со значком** на 1280×720 и телефоне. → Проверка в Playwright на 1280×800 и 740×360; на низком окне полоса скрыта, как у «Интервалов» (ряд — `C-APP-5`).
- **Правило пары делает порядок узнаваемым.** → 0,5 вместо «всегда» (`C-SOL-3` Р-19); тест на частоту по детерминированному `random`.
