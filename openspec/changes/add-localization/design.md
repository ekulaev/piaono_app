# Design

## Context

Тексты сегодня живут в трёх местах: JSX экранов (`ui/`), словари `ui/hints/hints.ts` и
`ui/connectionTexts.ts`, и логика упражнений (`engine/`): `modes.ts` (названия режимов),
`rhythm/figures.ts` (подписи фигур), `stats/summary.ts` (заголовки списков),
`stats/improvements.ts` (готовые строки «точнее / быстрее», «(бас)», «с»). Дата сборки собирается
вручную (`ui/settings/buildDate.ts`), склонение «попыток» — в строке. Заголовок и `lang="ru"` зашиты
в `index.html`, манифест — в `vite.config.ts`. Настройки читаются один раз в `App` (`settingsRef`) и
сохраняются целиком (`storage/settings.ts`). Мотивация и объём — `proposal.md`, требования — `specs/`.

## Goals / Non-Goals

**Goals:**
- Один механизм поиска текста для `ui/`; движок языка не знает (CLAUDE.md §4).
- Русский визуально и по смыслу неотличим от нынешнего.
- Новый язык — один файл, без правки экранов.

**Non-Goals:**
- Языки сверх русского и английского, перевод названий нот, письмо справа налево, загрузка переводов
  с сервера.
- Изменение поведения чего-либо кроме языка и расположения кнопки в панели.

## Decisions

**D1. Файлы — TypeScript-модули `src/i18n/locales/<код>.ts`, а не JSON.** Один файл на язык, код в
имени (`ru.ts`, `en.ts`). Типизация: ключи задаёт `en.ts` (язык по умолчанию), TypeScript и тест
сверяют, что у `ru` те же ключи. Формы числительных — в самом файле (объект форм), без функций.
*Альтернатива — JSON:* проще для переводчика, но нет проверки ключей на сборке; для проекта с одним
владельцем и компилятором выигрывает типизация.

**D2. Реестр языков — `import.meta.glob('./locales/*.ts', { eager: true })`.** Новый файл попадает в
список без правки кода (OB-9); `eager` — все переводы в основном бандле, поэтому офлайн-кеш Workbox
их покрывает без отдельной настройки. Каждый файл отдаёт также свои данные: код, название на своём
языке, идентификатор флага. *Альтернатива — ленивая подгрузка:* лишний шанс «нет сети — нет языка»
ради нескольких килобайт.

**D3. Поиск текста — чистая функция `translate(locale, key, params)` в `src/i18n/`:** текст языка,
иначе английский (OB-8), параметры `{n}`, формы числительных через `Intl.PluralRules`, числа и дата —
через `Intl.NumberFormat` / `Intl.DateTimeFormat` по коду языка. Выбор языка при запуске —
чистая `resolveLanguage(сохранённый, языкиСистемы, доступные)`: сначала сохранённый (если он есть
среди доступных), затем первый подходящий из `navigator.languages` с учётом региона, иначе `en`
(OB-5…OB-7). Обе функции покрываются тестами; слой `src/i18n/` не зависит от React и от `engine/`.

**D4. React: провайдер и хук `useT()` в `src/ui/i18n/`.** Язык — состояние провайдера; смена языка
перерисовывает дерево на месте (OB-4), `App`, MIDI-подписка и упражнения не перемонтируются,
поэтому связь, журнал и упражнение живут дальше. Выбор записывается в настройки через уже
существующий `updateSettings` (`App` владеет настройками). Провайдер же выставляет
`document.documentElement.lang`, `document.title` и `<meta name="description">` (OB-11).

**D5. Настройки: необязательное поле `language` в `piaono.settings.v1`.** Отсутствует или
неизвестно → `null` («следовать системе»); язык записывается только после выбора ученика. Ключ не
меняется, миграции нет (CLAUDE.md §7); тест на чтение настроек без поля и с мусором в нём. Проверка
«такой язык есть» — не в `storage/`, а в `resolveLanguage` (хранилище не знает о доступных языках).

**D6. Движок отдаёт идентификаторы и числа, слова подставляет `ui/`.**
- `modes.ts`: убрать `title`, названия — по идентификатору режима.
- `figures.ts`: убрать `label`, подпись — по `FigureId`.
- `summary.ts`: вместо `title` — вид списка (`note`/`interval`/`figure`).
- `improvements.ts`: вместо готовой строки — структура (вид, место, метрика, «было / стало»); строку
  собирает интерфейс (формат времени и процентов — по языку, «(бас)» — по ключу).
Тесты движка переписываются на структуры вместо русских строк. Поведение не меняется.

**D7. Подсказки (`hints.ts`): блоки хранят ключи, не тексты.** Структура подсказки (порядок блоков,
нотные и ритмические примеры) остаётся в `hints.ts`, слова — в файлах перевода; `HintDialog` и
`HintNotes` берут текст через `useT()`. Нотные примеры (ключ, высоты) не переводятся.

**D8. Кнопка и список языка — отдельный компонент `ui/topbar/LanguageMenu`.** Кнопка с
`aria-haspopup` и `aria-expanded`, список — строки-кнопки ≥ 64 px, текущая — заливка и отметка.
Закрытие: повторное нажатие, касание вне (слушатель `pointerdown`, который **не** гасит касание —
нота под пальцем играет сразу, отклик упражнения не страдает), Esc с возвратом фокуса. Список
раскрывается вниз от панели; на время открытия он может закрывать верх стана (Р-26 в C-APP-3: решение
владельца); при нехватке высоты прокручивается сам список. Меню режимов и список языков не открыты одновременно: касание панели закрывает меню
режимов (как сейчас).

**D9. Флаги — значки SVG в `ui/icons`**, толстые контуры, рядом код языка при ширине ≥ 900 px
(`rem`-медиазапрос от 16 px, как у подписей панели). Идентификатор флага берётся из файла языка; у
языка без флага показывается его код в нейтральной рамке — новый язык не требует правки
экранов.

**D10. Статичные оболочки.** `index.html` — английский заголовок, описание и `lang="en"`; манифест в
`vite.config.ts` — `name: 'Sight-reading Trainer'`, `short_name: 'Notes'`, `lang: 'en'`, описание
английское.

## Risks / Trade-offs

- [Много файлов затронуто механически, легко ошибиться в слове] → переносим русские тексты дословно;
  проверка: headless-снимки каждого экрана на 1280×800 до и после, русский текст совпадает.
- [Английские тексты длиннее или короче русских, вёрстка «прыгает» или обрезает] → проверка каждого
  экрана на обоих языках на 1280×800 и 740×360; кнопки панели держат ширину без переноса.
- [Ключи разъезжаются между языками] → тест: набор ключей `ru` равен набору `en`.
- [Имя значка на планшете меняется на английское; Android может обновить его не сразу] → описано в
  PR; решение владельца Р-14 (C-APP-3).
- [Если язык системы планшета английский, приложение после обновления станет английским] → в PR
  чек-лист: выбрать «Русский» в списке; выбор сохранится.
- [Правка `engine/` ломает тесты, написанные на русских строках] → тесты переписываются на структуры в
  той же задаче, что и движок.

## Migration Plan

Миграции данных нет. Деплой — обычный (слияние в `main`, кнопка «Обновить»). Откат — отдельный
revert-PR: поле языка в настройках старая версия игнорирует.
