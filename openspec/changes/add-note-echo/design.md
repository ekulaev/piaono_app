# Design

## Context

См. proposal.md. Сверка с кодом (explore по C-STF-8): оба источника нажатий — пианино и касание — сходятся в `handleKeyInput` (`ui/App.tsx`) и дают `playedNote` (высота, источник, время); ноты вне 88 клавиш проходят без проверки диапазона. Главный экран — `WaitingScreen` (сетка «стан / ряд кнопок», клавиатурный блок снизу). На 1280×800 зона стана 338 px, ряд кнопок 63 px; на 740×360 зона стана уже 0. В `Controls.tsx` нет ползунков (правило «мелкая цель»), есть `Stepper` с целым шагом. `formatSeconds` пишет один знак после запятой. Тексты — только через файлы перевода (`ru.ts`, `en.ts`, тест сверяет наборы ключей).

## Goals / Non-Goals

**Goals:** отклик ≤ 50 мс без нагрузки на MIDI; логика карточек — чистые функции с тестами; интерфейс тонкий; настройка читается из старых данных без ошибок.

**Non-Goals:** звук, сила нажатия, журнал, выключатель показа, бемоли, телефон, слоговые имена на кириллице.

## Decisions

**1. Чистая логика в `engine/noteEcho/`, слов там нет.**
- `describeNote(pitch)` → `{ solfege, letter, sharp, octave }` (идентификаторы и числа). «Do♯», «C♯4» собирает `ui/`. Отдельная от `midi/noteNames.ts`: там журнал «Проверки пианино» с «#» остаётся как есть.
- Слоты — массив из 5 ячеек `Card | null`. `addCard(slots, card)`: пусто → ячейка 0; правая видимая `r < 4` → `r + 1`; `r = 4` → сдвиг влево на одну (ячейка 0 теряется — она старейшая), карточка в ячейку 4. `removeCard(slots, id)` обнуляет ячейку, остальные не трогает.
- Альтернатива: компактный список без дыр. Отклонён: карточки прыгали бы при каждом исчезновении (CLAUDE.md §6).

**2. Хук `useNoteEcho(durationMs)` в `ui/echo/`, таймер на каждую карточку.** Хук держит слоты в `useState`, на каждое `push(pitch)` делает `setTimeout` на время показа, действовавшее в момент нажатия (старые карточки времени не меняют, OB-12); таймеры снимаются при размонтировании. Вызывается из `handleKeyInput` рядом с `playedInExercise` и др. Альтернатива — `requestAnimationFrame`-цикл: лишняя работа без выгоды.

**3. Полоса — отдельная строка сетки `WaitingScreen`.** Строки: стан `1fr`, полоса фиксированной высоты, ряд кнопок. Полоса получает `aria-hidden`, на `max-height: 30rem` скрыта целиком (`display: none`), строка сетки под неё на низком экране убрана, чтобы не прибавлять зазор; карточки при этом создаются, но не видны. Высота подбирается проверкой в браузере: стан на 1280×800 должен остаться читаемым (ориентир ~4 rem на полосу; стан ~270 px).

**4. Названия октав — ключи перевода** `octave.0`…`octave.8` и `octave.other` с `{n}`; мелкая строка собирается ключом `echo.small` из буквенного названия и названия октавы. Крупные имена (Do Re Mi…) в переводы не входят: на обоих языках одни и те же (C-STF-8, Р-2, Р-10).

**5. Настройка — поле `noteEchoMs` в `Settings`** (`piaono.settings.v1` без смены версии): число 500…5000 с шагом 500; нет поля, не число, вне диапазона — 1000. Значение живёт в состоянии `Main` (как «Глиссандо»), чтобы строка настроек и хук видели одно число.

**6. `Stepper` обобщается** двумя необязательными свойствами: `step` (по умолчанию 1) и `format` (по умолчанию число как есть). Остальные потребители не меняются. Для секунд передаётся `formatSeconds`. Значение хранится в миллисекундах, поэтому арифметика целая.

## Risks / Trade-offs

- [Полоса отнимает ~4 rem высоты у стана на планшете] → проверка на 1280×800 при реализации; при тесноте уменьшить высоту полосы, но не размеры шрифта из спецификации.
- [Всплеск нажатий (глиссандо, быстрый пассаж) создаёт много таймеров] → карточек не больше пяти на экране, а таймеры лёгкие; число нажатий в секунду у человека ограничено.
- [Карточка не связана с оценкой, ученик может принять её за подсказку «что играть»] → нейтральный цвет, без акцента (INV-2).
- [Правка `Stepper` задевает настройки режимов] → значения по умолчанию сохраняют прежнее поведение; существующие тесты и ручная проверка меню режимов.

## Migration Plan

Миграции данных нет: новое необязательное поле читается с запасным значением. Откат — удалить поле, старые версии его игнорируют.
