# Design

## Context

Источник требований — `PSD/specifications/M-APP/C-APP-5 Компактный экран.md` (ред. 4); мотивация — в `proposal.md`.

Что есть сейчас (по коду и замерам на dev-сборке):

- `Main` в `ui/App.tsx` владеет состоянием связи (`connectionState`), состоянием клавиатуры (`keyboard`, `handleKeyInput`), настройками (`settingsRef`, `updateSettings`, как `keyLabels` и `noteEchoEnabled`) и всеми запусками упражнений через `startMode`.
- Блок клавиатуры (`Keyboard`: мини-клавиатура, кнопки прокрутки, легенда сольфеджио, отметки ✓/✗, фокус и авто-сдвиг, `onCapacity`) всегда передаётся в `WaitingScreen` и стоит в нижней строке сетки `minmax(0, 1fr) min-content`. Без блока строка схлопывается, нотная зона получает всю высоту.
- «Старт» вызывается из `WaitingScreen`, из `ModeMenu` (через `confirmMode(true)`), из итогов («Повторить», «Новая»), кнопка уже умеет `aria-disabled` (`.button[aria-disabled='true']`).
- `WarmupSettingsForm` уже понимает `capacity: null` как «клавиатуры нет» (нет авто-сдвига и предупреждения); авто-сдвиг в `App` пропускается, если вместимость неизвестна.
- Настройки хранятся целиком (`updateSettings` пишет весь объект), все поля булевы или значения с умолчанием, чтение с заменой повреждённой части по умолчанию (`storage/settings.ts`).
- Низкий экран (`max-height: 30rem`) — отдельная существующая раскладка кнопок; её пороги не связаны с порогами компактного экрана и не меняются.
- Замер (CSS px, высота зоны нот / блока клавиатуры): 1280×720 — 189 / 243; 960×600 — 111 / 213; 740×360 — 0 / 207.

## Goals / Non-Goals

**Goals:**
- Один источник истины для «компактного экрана» в `ui/`, без дублирования порогов в CSS и в коде.
- Блокировка запуска в одном месте, чтобы ни один путь («Старт», меню, итоги) не обходил её.
- Поведение на обычном экране при значении по умолчанию не меняется (главный экран и ряд кнопок как раньше).

**Non-Goals:**
- Флажок скрытия клавиатуры на главном экране, клавиатура на компактном экране (беклог `Б-APP-3`, Р-15, Р-18).
- Тесный ряд кнопок на 960–1100 px (`Б-APP-4`).
- Правка `engine/` логики упражнений, `midi/` и ключей хранилища; правка документов `PSD/` соседних компонентов (после реализации, в дельте).
- Показ имён нажатых нот на низком экране (`C-STF-8`, OB-17).

## Decisions

### 1. Размер окна — через `matchMedia` в одном хуке, пороги — константы

Хук `useCompactScreen` (`ui/screen/useCompactScreen.ts`) подписывается на `matchMedia('(height < 35rem) or (width < 60rem)')` и возвращает булево; значения порогов — константы в одном модуле. Эта же пара констант питает чистую функцию `isCompactSize(width, height)` (rem = 16 px, как в медиазапросах) для тестов. CSS порогов не знает: компактный экран не включает правил CSS, а меняет, какие элементы рендерит React (нет блока клавиатуры, другое содержимое нотной зоны), поэтому расхождения разметки и интерфейса не возникает (Р-11).

Альтернативы: `window.innerWidth/innerHeight` и `resize` (дребезг, не учитывает масштаб в rem так же, как CSS); разметка только через CSS `@media` (не скрывает компонент, остаются касания и подписки). Отвергнуты.

### 2. Что считать «показана» и «нечем играть» — чистые функции

В `engine/keyboard/availability.ts`: `keyboardShown(compact, setting)` и `canPlay(shown, pianoConnected)`; `pianoConnected` — булево из состояния связи (в `engine/` типов `midi/` нет). Правила целиком в тестах (таблица). `App` считает их один раз и раздаёт вниз.

### 3. Настройка — булево `keyboardVisible`, по умолчанию `true`

Поле в `Settings` рядом с `keyLabels`; читается как `typeof === 'boolean' ? значение : true`; ключ `piaono.settings.v1` не меняется, миграции нет. Тест на чтение старой записи без поля и на повреждённое значение (`CLAUDE.md` §7). Различать «не менял» и «выбрал показывать» не нужно (Р-16). Размер окна ничего не пишет.

### 4. Одна точка блокировки запуска и остановки

`startMode` начинается с `if (!canPlay) return`: этот путь проходят «Старт», меню режимов и итоги. Для вида `WaitingScreen` и `ModeMenu` получают `startDisabled` и ставят `aria-disabled` на «Старт» (уже существующий приём: кнопка остаётся в фокусе, состояние различается заливкой, не только цветом). Остановка — эффект в `Main`: если упражнение идёт и `!canPlay`, вызывается `stopExercises()` (тот же путь, что у «Настроек»: без итога и без записи прерванной попытки).

Альтернатива — блокировать только кнопки: оставляла бы пути запуска из итогов и меню. Отвергнута.

### 5. Приглашение — новый компонент вместо содержимого нотной зоны

`ui/PlayInvite.tsx` (строка по состоянию связи, кнопка «Настройки», вторая строка при скрытой настройкой клавиатуре) подставляется в `Main` в переменную `staff` последним, поверх итогов и «Ещё нет прогресса». Исключение: пока в меню режимов открыты настройки «Разминки», остаётся предпросмотр (C-STF-9, OB-9) — приглашение не нужно, пока меню закрывает главный экран. Соответствие состояния связи строке и ключу перевода — чистая функция с тестом. Зона та же `staff-zone`, что у «Ещё нет прогресса», поэтому ряд кнопок не двигается (NFR-1 спецификации).

«Подключаемся» тоже даёт приглашение («Ищу пианино…»): на запуске и после сна зона не меняет размер и не мигает разными экранами (Р-5).

### 6. Без клавиатуры `keyboard` не рендерится

`WaitingScreen` получает `keyboard: ReactNode | null`; `labelsControl` — `null` (флажок подписей скрыт, сохранённое значение не меняется). Перед скрытием клавиатуры `App` сообщает вместимость `null` (эффект по `keyboardShown`), чтобы «Разминка» не показывала устаревшее предупреждение; авто-сдвиг уже пропускается при `null`. Нажатые касанием клавиши отпускаются новым входом `engine/keyboard`: `releaseTouches` (снимает только касания, пианино не трогает, INV-4 `C-KBD-1`), который `App` отправляет при переходе `keyboardShown → false`.

### 7. «Настройки»: строка и скрытие «Глиссандо»

`SettingsScreen` получает `keyboardShown`, `compact`, `keyboardVisible`, `onChangeKeyboardVisible`. Строка «Экранная клавиатура» (`Toggle compact`, как у «Показывать нажатые ноты») стоит перед «Глиссандо» и не рисуется на компактном экране; «Глиссандо» не рисуется, пока клавиатура не показана. Значение глиссандо не меняется.

### 8. Легенда сольфеджио без клавиатуры — ряд в нотной зоне

Данные не меняются: `view.legend(t)` отдаёт подпись по ступени 0–11. Новый компонент `ui/solfege/LegendRow.tsx` рисует пары «имя ступени — подпись» без октав: имя берётся тем же названием нот, что в полосе нажатых нот (`C-STF-8`), порядок — по ступени от «до»; значки (длительности) отображаются тем же способом, что в `Keyboard`. Ряд ставится под станом в `SolfegeStaff` (`legend` — необязательное свойство); флажком `wrap` переносится на строки, шрифт не мельче 18 px. Отметки ✓/✗ на клавишах без клавиатуры не рисуются: оценка уже есть на стане (`C-SOL-1`, Р-26).

Риск: у «Интервалов» до 13 пар на 740×360. Проверяется в браузере; если не помещается — уменьшается высота стана (в сторону большего числа строк), а не размер шрифта.

### 9. Переводы

Новые ключи в `ru.ts` и `en.ts` (строки приглашений, вторая строка, «Экранная клавиатура»); слов в компонентах нет. Тексты — из приложения В `C-APP-5`.

## Risks / Trade-offs

- [Легенда сольфеджио не помещается на 740×360 или 360×740] → ряд переносится на строки, при нехватке высоты стан сжимается; проверка в браузере обязательна, результат записывается в `tasks.md`.
- [Окно ошибочно считается компактным при увеличенном масштабе] → с пианино на связи всё работает, без пианино видно приглашение и открываются «Настройки»; запас по масштабу ~1,28 раза (Р-12).
- [Вспышка приглашения «Ищу пианино…» на запуске при скрытой клавиатуре] → терпимо (одна строка в той же зоне), проверяется владельцем на планшете.
- [Остановка упражнения при кратком сбое связи при скрытой клавиатуре] → принято (Р-6); данные уже записанных событий сохраняются, прерванная попытка не пишется.
- [Устаревшая вместимость клавиатуры после скрытия] → сброс в `null` по `keyboardShown`.
- [Зависшие касания при сжатии окна] → `releaseTouches` при скрытии клавиатуры.
- [Расхождение пороговых значений между кодом и документами] → пороги в одном модуле констант; `C-KBD-3` Р-18 считает компактными окна 64rem, а здесь 60rem — приведётся в дельте документов (`C-APP-5`, Р-10, Р-20).

## Migration Plan

Миграции данных нет: поле `keyboardVisible` отсутствует в старых записях и читается как `true`. Откат — удалить чтение поля: лишнее поле в записи ничему не мешает. Слияние в `main` деплоится на планшет; пользователь получает прежний главный экран и одну новую строку в «Настройках».

## Open Questions

- Точный вид ряда легенды на малых окнах (число строк, расстояния) — уточняется при реализации по результату проверки в браузере; на требования не влияет.
