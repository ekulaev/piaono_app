# Design

## Context

См. proposal.md. Сверка с кодом (explore по C-STF-9):

- «Разминка» зашита: `TRAVEL_MS` — константа в `engine/staff/exercise.ts` (читают `step` и `progress`); диапазоны `CLEF_RANGES` и пары «нота + ключ» — константы в `engine/staff/pickNote.ts`; `StaffNote` — только `{pitch, clef}`; `vexKey(pitch)` знает только белые клавиши; ширина стана `0.9` написана в двух местах (`ui/staff/staffDrawing.ts`, `ui/staff/staffHooks.ts`).
- Меню режимов — автомат `engine/modes/modeMenu.ts`; у экрана режима есть черновик настроек (`draft`), `ModeSettings = SequenceSettings | RhythmSettings | null`, у «Разминки» `hasSettings: false`. Меню — `position: fixed`, справа, шириной `min(100%, clamp(20rem, 40vw, 30rem))`.
- Стан рисует VexFlow: `makeStave` + `drawNote`; путь ноты кончается на `stave.getNoteStartX()`, поэтому после `addKeySignature` нота остановится у знаков сама. Запас по высоте — `TOP_MARGIN = 40` единиц (4 межлинейных промежутка): три добавочные линии с головкой уже помещаются.
- Видимая часть клавиатуры живёт внутри `Keyboard` (`useState`), снаружи её двигает только пропс `focus` (`KeyboardFocus` с `token`, им пользуются «Последовательности»: `centerStartOn`). `computeLayout` даёт `visibleWhiteCount` (52, если видны все).
- Выпадающий список есть в `ui/topbar/LanguageMenu.tsx` (закрытие касанием вне списка и Esc, выбор применяется сразу); в `ui/controls/Controls.tsx` только `ChoiceGroup`, `Stepper`, `Toggle`.
- Имена нот (слог, буква, октава) уже даёт `engine/noteEcho/describeNote.ts` (C-STF-8, change `add-note-echo` в `main`); бемолей в нём нет.
- Настройки: `storage/settings.ts`, `modeSettings` по режимам, чтение поле за полем; ключ `piaono.settings.v1`.

## Goals / Non-Goals

**Goals:** «Разминка» с настройками по умолчанию ведёт себя ровно как раньше (проверяется тестом на распределение); логика — чистые функции в `engine/` с тестами, UI тонкий; MIDI-слой не затрагивается; данные читаются без миграции.

**Non-Goals:** предпросмотр и настройки на компактном экране (`Б-STF-5`, `C-APP-5`); хроматика, гармонический минор; тональности в других режимах; звук; рефакторинг `LanguageMenu` сверх необходимого для общего списка.

## Decisions

**1. Нота хранит написание, а не только высоту.** Новый тип в `engine/warmup/`: ступень (буква C–B и октава), знак, показываемый перед нотой (`natural` | нет), звучащая высота `pitch`, ключ `clef`. Знак тональности не рисуется у ноты, он в ключе. `pickNote` возвращает эту ноту; статистика и проверка нажатия по-прежнему используют `pitch` и `clef` (формат `clef:pitch` не меняется, старые данные читаются). Альтернатива — хранить только высоту и восстанавливать написание по тональности: не различает F♯ и G♭ и не позволяет показать бекар.

**2. 15 тональностей — таблица в `engine/warmup/keys.ts`.** Одна запись на набор знаков при ключе: число знаков, диез или бемоль, порядок знаков, смещение по буквам (C…B → −1, 0, +1), название для VexFlow. Мажор и минор одних знаков играются одинаково (Р-2), поэтому отдельных записей для минора нет: идентификатор записи — мажорный (`G-major`, `Bb-major`; он же хранится в настройках), а минорный параллельный тоникой (`E-minor`) нужен только подписи. Строки списка строятся из таблицы по порядку (0, 1♯…7♯, 1♭…7♭); название строки — один ключ перевода на запись (`warmupform.key.<id>`) с двумя половинами «<Мажор> / <Минор>», обе с заглавной буквы; число знаков с ♯ или ♭ добавляет форма, знаки не переводятся.

**3. Набор нот — чистая функция `buildPool(settings)`.** Для каждого включённого ключа берутся ступени от нижней до верхней границы; для ступени со знаком при ключе при включённом бекаре добавляется второй вариант «с бекаром». Возвращаются пары `{note, base}` как в нынешнем `PAIRS`: база ноты 1 (общей зоны — 1/число ключей), вес трудности умножается на неё (`weights.note(clef, pitch)`), выбор — прежний `weightedPick`. Ноты общей зоны определяются по ступени, а не по высоте. Тест: при настройках по умолчанию набор равен нынешнему (те же пары и базы). Бекар — «ещё одна нота в наборе», а не «подбросить монету»: отдельной вероятности нет, трудные чаще автоматически (Р-10).

**4. Время хода — поле состояния, а не константа.** `TRAVEL_MS` остаётся значением по умолчанию; `start(now, random, weights, settings)` кладёт `travelMs` в состояние, `step` и `progress` читают его оттуда. Так чистые функции остаются без глобального состояния, тесты задают любое время.

**5. Настройки «Разминки» — чистый модуль `engine/warmup/settings.ts`.** Тип `WarmupSettings` (время, ключ, диапазоны как индексы ступеней, тональность, бекар, авто-сдвиг), `DEFAULT_WARMUP_SETTINGS`, `readWarmupSettings(unknown)` — поле за полем, как у `readSequenceSettings`: нет поля или значение вне допустимых границ — значение по умолчанию только для этого поля; диапазон, нарушающий «не меньше двух нот», заменяется диапазоном по умолчанию целиком. `ModeSettings` расширяется типом `WarmupSettings`, `hasSettings` у «Разминки» становится `true`, `modeSettings.warmup` в `storage/settings.ts`. Ключ `piaono.settings.v1` не меняется: поля необязательные. Откат — удалить поле, старые версии его игнорируют.

**6. Предпросмотр — в зоне стана главного экрана, от черновика меню.** `ui/warmup/WarmupPreview.tsx` рисует станы по `menu.draft`, когда открыт экран режима «Разминка»; ноты предпросмотра раскладываются отдельной функцией рисования в `ui/staff/` (по одной ноте на ступень, равные промежутки, подсветка диапазона заполненной головкой на подложке). Ширина стана — как у обычного (95 %), а область нот ограничена свободной частью зоны: её правый край — левый край настоящей панели `.mode-menu`, который предпросмотр измеряет при отрисовке и при изменении размера окна. Так предпросмотр не расходится с меню, а формула ширины живёт только в CSS меню. Высота стана предпросмотра — всегда половина зоны: один ключ стоит по центру и не крупнее, чем при двух (иначе головки 23 нот наезжали бы друг на друга). Зона и стан не меняют размер при открытии меню (требование `mode-menu`). Альтернатива — предпросмотр в самом меню: узко (23 ноты на 20–30 rem), нечитаемо при слабом зрении (Р-8).

**7. Ширина стана 95 % — одна константа.** `STAFF_WIDTH_RATIO` в `staffDrawing.ts`, читают `staffGeometry` и `staffHooks.ts` (раньше `0.9` дважды). `SequenceStaff` и `RhythmStaff` берут размеры из той же геометрии — проверить при реализации, что их станы не ломаются (Р-9).

**8. Знаки при ключе и бекар — средствами VexFlow.** `stave.addKeySignature(...)` сразу после ключа (только если на стане есть ключ), `Accidental('n')` для ноты с бекаром, Ноту строим по ступени и позиции на стане, а модификатор знака добавляем только для бекара: у ноты тональности знака рядом с головкой нет, он уже в начале стана. Путь ноты по `getNoteStartX()` уже учитывает знаки. Добавочные линии: запас `TOP_MARGIN` вмещает три, правится только текст требования; тест на отсутствие обрезки у `E3`, `F6`, `G1`, `A4`.

**9. Ползунки — новые элементы `Slider` и `RangeSlider` в `ui/controls/`.** Свои, не `<input type=range>`: нужны две ручки, цель касания 56×56, контраст 7:1, видимый фокус, формат подписи. Ручка — `role="slider"` с `aria-valuemin/max/now`, управление указателем (pointer events, захват) и клавишами (стрелки, Home/End). Положение — целый индекс шага; `RangeSlider` держит минимум две ноты между ручками. Состояние снаружи (контролируемые компоненты), как у `Stepper`. Альтернатива — нативный `range`: две ручки не поддерживает, внешний вид не по конституции.

**10. Выпадающий список — общий элемент `Dropdown`.** Поведение берётся из `LanguageMenu` (открытие кнопкой, закрытие выбором, касанием вне и Esc, возврат фокуса на кнопку). `LanguageMenu` на него не переведён: у него другой вид (флаги, всплывающий список в верхней панели), перенос — риск для рабочего экрана без выгоды; `Dropdown` повторяет его поведение (закрытие выбором, касанием вне списка и Esc, возврат фокуса) и раскрывается в потоке настроек. Список в 30 строк прокручивается внутри списка, не страницей (`NFR-2` меню).

**11. Авто-сдвиг и вместимость — через `Keyboard`.** `KeyboardFocus` получает необязательное `align: 'left'` (по умолчанию — центрирование, «Последовательности» не меняются); новая функция в `engine/keyboard/layout.ts` ставит `start` так, чтобы нужная нота была первой видимой, с зажимом по краю (`clampStart`). `Keyboard` сообщает наружу вместимость (`onCapacity(count | null)`), `null` — если клавиатуры нет. В `App` запоминается ключ последней сдвинутой ноты в сессии: при `start` и при появлении ноты другого ключа — новый `focus` с `align: 'left'` и нижней нотой диапазона этого ключа (Р-15). Сброс — на «Стоп».

**12. Предупреждение о диапазоне — чистая функция.** `rangeExceedsCapacity(rangeNoteCount, capacity)` (`capacity == null` → нет предупреждения); форма настроек получает вместимость из `App`, отметка — значок и подпись, различимые формой.

**13. Названия нот со знаками.** Чистая функция `noteLabel(pitch, key)` в `engine/warmup/`: если высота принадлежит тональности — написание тональности (♯ или ♭), иначе диез (как `describeNote`). Итог «Разминки» и «Прогресс» используют её с текущей тональностью (Р-19). Отдельной статистики по тональностям нет (Р-14).

## Risks / Trade-offs

- [Самая большая правка ежедневного режима] → значения по умолчанию воспроизводят прежнее поведение; тест на совпадение набора и базовых вероятностей с нынешними; данные читаются поле за полем; ручная проверка на планшете «без изменений нажать Старт».
- [23 ноты в свободной части зоны на планшете с семью знаками тесно (запас ≈ 1,25 раза)] → проверка в Chromium на 1280×800 при семи диезах и семи бемолях, ноты не наезжают друг на друга; гейт из спецификации.
- [Два стана и 23 ноты нечитаемы на телефоне 740×360] → вне этого change (`Б-STF-5`, `C-APP-5`); на компактном экране клавиатуры нет, флажок и предупреждение скрыты.
- [Правка `staffGeometry` и 95 % задевает «Последовательности», «Контур», «Ритм»] → снимки и ручная проверка на 1280×800 во всех режимах; ширина — одна константа.
- [Пропс `focus` у `Keyboard` меняется для «Последовательностей»] → новое поле необязательное, поведение по умолчанию прежнее, тест на центрирование остаётся.
- [Два источника правды о ширине меню (CSS меню и расчёт предпросмотра)] → предпросмотр измеряет настоящую панель, формулы не дублируются.
- [Список языков и `Dropdown` — два похожих элемента] → поведение совпадает (проверено вручную); перенос `LanguageMenu` — отдельным шагом, если понадобится.
- [Своя реализация ползунка: ошибки жестов и клавиатуры] → тесты чистой логики (шаг, границы, минимум двух нот), проверка касанием в Chromium (Playwright) и с клавиатуры.

## Migration Plan

Миграции данных нет: новые необязательные поля читаются с запасным значением. Статистика не трогается. Откат — удалить поле `modeSettings.warmup`, старые версии его игнорируют.
