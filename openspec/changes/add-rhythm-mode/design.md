# Design

## Context

Мотивация — proposal.md, раздел Why. Требования — `specs/rhythm-mode` и изменения `mode-menu`,
`practice-stats`.

Что есть и что мешает:

- **Время нажатия теряется.**
  - `midi/` отдаёт `NoteOn { pitch, velocity, time }`, где `time` — это `event.timeStamp` MIDI в
    шкале `performance.now`.
  - `KeyInput.pianoDown` и `touchDown` времени не несут, `PlayedNote` тоже.
  - Упражнения получают `played(pitch)` и берут `performance.now()` в момент обработки. Для
    «Последовательностей» это не важно, для ритма — это ошибка измерения (NFR-2).
- **Для рисунка ничего нет.** Отрисовка есть только для головок без штилей (`sequenceDrawing`) и для
  целой ноты (`staffDrawing`). Нет длительностей, пауз, вязок, размера и одной линии.
- **Статистика** (`engine/stats`):
  - таблицы только `notes` и `intervals`, события — `note` и `interval`;
  - `hasProgress` смотрит на ноты и интервалы;
  - `improvements` умеет подписи нот и интервалов;
  - режимов три.
- **Меню режимов.** `ModeSettings = SequenceSettings | null`; `ModeMenu` показывает
  `SequenceSettingsForm` для всего, кроме «Разминки».
- **Главный экран.**
  - `WaitingScreen` принимает `slotButton` — одну кнопку на месте «Проверки пианино».
  - Стан, итог или приглашение `App` кладёт в зону стана.
  - Флажок «Переключать автоматически» показывается при `activeMode !== 'warmup'` — для «Ритма»
    его надо исключить.

## Goals / Non-Goals

**Goals:**

- Вся логика ритма — чистые функции в `engine/rhythm/` с тестами: фигуры, генератор, подгонка темпа,
  оценка, автомат сессии, итог.
- Отклик на удар — сразу по первому нажатию, без ожидания окна. Для ритма аккорд — один удар:
  следующие нажатия в окне просто не считаются.
- Точность времени удара — время события, не обработки.

**Non-Goals:**

- Метроном и звук.
- Длительность удержания клавиши.
- Перевод других режимов на время события. Они остаются как есть: время события передаётся всем, но
  используется только ритмом.

## Decisions

### D1. Время нажатия через движок клавиатуры

- `KeyInput`: у `pianoDown` и `touchDown` появляется `time: number`.
- `PlayedNote.time` — время нажатия.
- `App` передаёт `event.time` (MIDI) и `Keyboard` — `event.timeStamp` (pointer). Обе величины в
  шкале `performance.now`.
- `reduce` переносит `time` во `PlayedNote` и больше ничего с ним не делает. Тесты клавиатуры
  дополняются полем.

**Альтернатива:** брать время отдельно, в обход движка клавиатуры. Отклонена: у касаний нет другого
пути, и слой `ui` полез бы в логику упражнения.

### D2. Фигуры и уровни — `engine/rhythm/figures.ts`

- Длительности в тиках, 1 тик = восьмая, доля (четверть) = 2 тика.
- `Figure { id, label, items: { ticks, rest }[] }`:

  | id             | Фигура                      | Тики      |
  | -------------- | --------------------------- | --------- |
  | `half`         | половинная                  | 4         |
  | `quarter`      | четверть                    | 2         |
  | `eighths`      | две восьмые                 | 1 + 1     |
  | `quarter-rest` | четвертная пауза            | 2 (пауза) |
  | `half-rest`    | половинная пауза            | 4 (пауза) |
  | `dotted`       | четверть с точкой и восьмая | 3 + 1     |

- `LEVELS[1..4]` — накопительные наборы по LIM-1.
- Каждая фигура занимает целое число долей и ставится с начала доли. Поэтому вязки восьмых всегда
  внутри доли, а точка не пересекает тактовую черту.

### D3. Генератор — `engine/rhythm/generate.ts`

- Такт заполняется фигурами, которые помещаются в оставшиеся доли. Выбор взвешен:
  `weightedPick(fitting, f => weights.figure(f.id))`.
- Первая фигура первого такта — не пауза.
- Если нот меньше 3 — рисунок строится заново, до 20 попыток. Гарантия: на каждом уровне есть
  четверть, а 3/4 из трёх четвертей даёт 3 ноты.
- `buildRhythmSession(settings, random, weights)` → массив рисунков. «Повторить» переиспользует его.
- Модель рисунка: `Pattern { meter, bars, figures: FigureId[], notes: { at, ticks, rest, figureIndex }[] }`,
  где `at` — начало в тиках.

### D4. Подгонка темпа и оценка — `engine/rhythm/evaluate.ts`

- Вход: места нот `x_i` (тики, без пауз) и времена ударов `t_i`.
- Линейная регрессия `t ≈ a + b·x` (наименьшие квадраты, формула в закрытом виде), `b` — мс на тик.
- Отклонение `d_i = t_i − (a + b·x_i)`, допуск `tol = 0.25 · minTicks · b`, где `minTicks` —
  самая короткая длительность рисунка.
- Оценка ноты: `|d| ≤ tol` → `onTime`; `d < 0` → `early`; иначе `late`.
- Инвариант пропорций (INV-2) выполняется автоматически: умножение всех интервалов на `k`
  масштабирует `b` и `d` одинаково.

### D5. Автомат — `engine/rhythm/session.ts`

```
 idle --start--> ready(p) --tap--> tapping(p, taps) --tap on last--> evaluated(p, marks)
                   ^  |                 |                                |    |
                   |  +--skip-----------+-------> next pattern / summary |    |
                   +------ restart -----+                                |    |
                   +---------------------- tap (new attempt) ------------+    |
                                           next ------------------------------+--> next / summary
```

- Удар: если после прошлого удара прошло меньше 50 мс — игнор (аккорд). Иначе время кладётся
  в `taps`.
- На последней ноте — `evaluate`, события статистики в сессию, фаза `evaluated`.
- `firstTryClean[p]` — первая оценённая попытка рисунка чистая.
- `stats: { before, events } | null` — как у «Последовательностей» (C-STF-4). События фигур:
  `{ kind: 'figure', key: id, outcome: clean | error, ms: null }`.
- `summarizeRhythm` — рисунки чисто с первой попытки, попытки, доля «вовремя», «рано», «поздно»,
  до 3 трудных фигур по доле ошибок.

### D6. Статистика — `engine/stats`

- `StatsMode` получает `rhythm`, `PracticeStats` — четвёртый режим.
- `ModeStats.figures: Record<FigureKey, ItemStats>`. При чтении отсутствующая таблица становится
  пустой — старые записи читаются.
- `StatEvent.kind`: добавляется `figure`. `applyEvents` раскладывает события по трём таблицам.
- `hasProgress` — ноты, интервалы **или** фигуры.
- `weightsFor(...).figure(id)` — вес по трудности; времени у фигур нет, трудность — доля ошибок.
- `improvements` проходит и по фигурам; подпись — название фигуры. Строки времени у фигур не
  возникают: `timeCount = 0`.

### D7. Отрисовка — `ui/rhythm/RhythmStaff.tsx`, `rhythmDrawing.ts`

- `Stave` с `numLines: 1`, `TimeSignature`, линии толще дефолта — как в `staffDrawing`.
- Ноты — `StaveNote` на одной высоте (`b/4`), штили вверх, паузы — `qr`/`hr`, точка — `Dot`.
- Восьмые одной фигуры — `Beam`. Между тактами — `BarNote`.
- Расстановка — `Voice` + `Formatter` по ширине стана.
- Отметки — по `getBoundingBox()` ноты, как в `sequenceDrawing`:
  - текущая — акцент + черта;
  - сыгранная — сплошная черта;
  - `onTime` — кольцо;
  - `early`/`late` — пунктирное кольцо и треугольник-путь под нотой.
- Перерисовка целиком при смене состояния: движения нет.

### D8. Настройки, меню, `App`

- `RhythmSettings { level: 1..4; meter: 3 | 4; bars: 1 | 2; patterns: 1..10 }`,
  `readRhythmSettings`. `Settings.modeSettings.rhythm`.
- `ModeSettings = SequenceSettings | RhythmSettings | null`. `ModeMenu` выбирает форму по режиму:
  `RhythmSettingsForm` на `ChoiceGroup` и `Stepper`.
- `MODES = [sequences, contour, rhythm, warmup]`.
- `useRhythmSession()` — хук без цикла кадров: таймеров в ритме нет.
- `App`:
  - `startMode('rhythm')`;
  - `playedNote` с временем идёт в ритм;
  - `slotButton` по фазе: «Пропустить» / «Сначала» / «Далее»;
  - в зоне стана `RhythmStaff` или `RhythmSummary`;
  - флажок «Переключать автоматически» — только для «Последовательностей» и «Контура»;
  - сохранение статистики «Ритма» — по событиям, как у других режимов.

## Risks / Trade-offs

- **[Допуск]** Четверть самой короткой длительности может оказаться строгим или мягким для живой
  игры. → Одна константа `TOLERANCE_SHARE = 0.25`, подбирается на планшете.
- **[Ускорение внутри рисунка]** Линейная подгонка предполагает ровный темп. Если ученик ускоряется,
  крайние ноты уйдут в «рано» или «поздно». → Это и есть ошибка ритма. Рисунки короткие, 1–2 такта.
- **[VexFlow: одна линия, вязки, паузы]** Первый раз в проекте. → Отдельная задача с
  headless-скриншотами до подключения к `App`. Запасной вариант — стан из 5 линий с нотами на средней.
- **[Время касаний]** `timeStamp` pointer-событий на Android может отставать от касания на кадр. →
  Для касаний допуск тот же. Основной источник — пианино, у него время точное.

## Migration Plan

- Новые поля хранения (`modeSettings.rhythm`, `stats.rhythm`, `figures` в режимах) необязательные.
  Отсутствуют — значения по умолчанию или пусто.
- Откат — revert PR. Старая версия игнорирует новые поля.
