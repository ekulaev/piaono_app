# Design

## Context

Мотивация — proposal.md, раздел Why. Требования — `specs/practice-stats`, изменения
`specs/sequences-mode` и `specs/staff-exercise`.

Как устроено сейчас:

- **`engine/sequences/session.ts`.** Чистый автомат сессии. В `StepRecord` есть `result`,
  `hadError`, `reactionMs`, `hinted`. Уровни подсказок пересчитываются при переходе в `finished`
  (`advance`), «Стоп» их не трогает. Ровно в этой точке появятся данные для статистики.
- **`engine/sequences/generate.ts`.** Выбирает равновероятно через `pickOne`, `pickDistinct`
  и `nextByInterval`: размер интервала, затем направление.
- **`engine/staff/exercise.ts`.** Автомат «Разминки»: `moving → correct → pause` или
  `moving → pause` (доехала). Ошибка видна только как `wrongUntil`. Факт «были неверные нажатия»
  и время верного нажатия не хранятся. `stop()` сразу возвращает `IDLE`. Итога нет.
- **`engine/staff/pickNote.ts`.** Выбирает равновероятную белую клавишу B1–D6, в общей зоне
  G3–F4 ключ — монеткой.
- **`storage/progress.ts`.** `saveHintProgress` пишет `{ hints }` целиком. Если положить
  статистику рядом, она будет стираться (C-STF-4, INV-4).
- **`ui/App.tsx`.** `stopExercises()` вызывается и «Стопом», и меню, и «Проверкой»: отличить
  «Стоп» (показать итог) от остальных (без итога) пока нельзя.

## Goals / Non-Goals

**Goals:**

- Статистика, трудность, веса, улучшения — чистые функции в `engine/stats/` с тестами.
- Без статистики генераторы выдают прежнее распределение и тратят `random()` столько же раз,
  сколько сейчас.
- Объём хранения фиксирован: только счётчики и среднее, без истории событий.

**Non-Goals:**

- Экран статистики и сброс (этап 8).
- Разные веса для разных диапазонов и настроек: статистика по ноте общая для всех диапазонов режима.

## Decisions

### D1. Модель — `engine/stats/stats.ts`

```
interface ItemStats {
  attempts: number   // все законченные попытки
  clean: number      // верно с первой попытки
  errors: number     // верно после ошибки
  skips: number      // «Пропустить» / «не успел» — отдельно от ошибок
  timeCount: number  // сколько времён учтено
  avgMs: number      // среднее время: окно до 20 последних, см. ниже
}
type ModeStats = { notes: Record<NoteKey, ItemStats>; intervals: Record<IntervalKey, ItemStats> }
type PracticeStats = { sequences: ModeStats; warmup: ModeStats }   // у «Разминки» intervals пуст
```

- `NoteKey = 'treble:64'`, `IntervalKey = 'up3'`.
- Среднее обновляется так: `avg += (ms − avg) / min(timeCount, 20)`. Первые 20 времён дают точное
  среднее, дальше свежие весят больше. История не хранится, объём фиксирован (NFR-1).

**Альтернатива:** хранить последние N времён. Отклонена: объём растёт в N раз, выигрыша для
MVP нет.

### D2. События сессии и слияние

- `StatEvent { kind: 'note' | 'interval'; key; outcome: 'clean' | 'error' | 'skip'; ms: number | null }`.
- Сессия копит события за сессию, а не саму статистику:
  - `applyEvents(before, events)` → новая статистика для сохранения;
  - `aggregate(events)` → статистика одной сессии для «Что улучшилось».

  Один источник правды, и слияние не нужно считать дважды.
- `sequenceEvents(sequence, records)`:
  - события нот: для аккорда — каждая нота;
  - события интервалов: между соседними шагами из одной ноты, с исходом второго шага;
  - `ms` только если `result === 'correct' && !hadError && !hinted`.
- `warmupEvent(result)` — одно событие ноты; «не успел» → `skip`.

### D3. Трудность и веса — `engine/stats/weights.ts`

- `medianAvg(items)`: медиана `avgMs` по местам с `timeCount > 0`. Если таких меньше 3, медианы
  нет и замедленность равна 0.
- `difficulty(item, median)`:
  - `attempts < 3` → 0,5;
  - иначе `max(fail, slow)`, где `fail = (errors + skips) / attempts`,
    `slow = clamp(avgMs / median − 1, 0, 1)`.
- `weightsFor(mode)` → `{ note(clef, pitch), interval(size, direction) }` с весом
  `1 + 2 × difficulty`. Место без статистики получает 0,5 → вес 2. Когда статистики нет совсем,
  все веса равны 2, и выбор равновероятный.
- `UNIFORM` — все веса 1: значение по умолчанию для генераторов и тестов.

### D4. Взвешенный выбор в генераторах

- `weightedPick(options, weight, random)` делает один вызов `random()`: `r × сумма`, первая
  накопленная сумма больше `r`. При равных весах результат совпадает с
  `options[floor(r × n)]`, поэтому прежние тесты с зерном не меняются.
- **`generate.ts`:**
  - якорь — вес его ноты;
  - `nextByInterval`: размер — вес `max` по помещающимся направлениям от
    `weights.interval(size, dir)`; направление — `interval × note(цель)`;
  - `pickDistinct` — последовательный взвешенный выбор без повторов.
- **`pickNote.ts`:** пары `(pitch, clef)`, базовый вес 1 (0,5 в общей зоне — прежняя монетка),
  умноженный на `note(clef, pitch)`. При равных весах распределение прежнее, `random()`
  вызывается один раз вместо двух — тест «Общая зона» проверяет только ключ, поэтому допустимо.

### D5. «Разминка» получает исходы и итог — `engine/staff/exercise.ts`

- В `moving` появляется поле `hadError` (ставится при закрытии группы без верной ноты).
- В каждом не-idle состоянии есть поле `results: NoteResult[]`, где
  `NoteResult { pitch, clef, outcome, ms }`. Результат дописывается при `correct` и при
  прибытии к ключу.
- Новая фаза `summary { results }`:
  - `finish(state)` — «Стоп»: `summary`, если результаты есть, иначе `IDLE`;
  - `stop()` — меню или «Проверка»: `IDLE` без итога;
  - `start` из `summary` начинает новую сессию с пустыми результатами.
- `summarizeWarmup(results)` → счётчики, точность, до 5 медленных.

### D6. Автомат «Последовательностей»

- В `Common` добавляется `stats: { before: ModeStats; events: StatEvent[] } | null`. `advance`
  при переходе в `finished` дописывает `sequenceEvents(...)`. `summary` сохраняет `stats`.
- `startSession(…, now, hints, stats)` — последний необязательный параметр. `repeat` начинает с
  `before = applyEvents(before, events)`: следующая сессия сравнивается с обновлённой историей.

### D7. Хранение — `storage/progress.ts`

- Одна запись `piaono.progress.v1 = { hints, stats }`.
- `loadProgress()` → `{ hints, stats }`, каждое поле читается независимо
  (`readHintProgress`, `readPracticeStats`): повреждённый режим — пустой.
- `saveHintProgress(hints)` и `saveModeStats(mode, stats)` делают «прочитать — заменить своё
  поле — записать». Так выполняется INV-4, а старые вызовы не меняются.

### D8. Встраивание в UI

- `App`:
  - при «Старт» загружает прогресс; веса и `before` передаёт в сессию и в «Разминку»;
  - сохраняет `applyEvents(before, events)`, когда растёт число событий (эффект по длине);
  - «Стоп» → `finish` для «Разминки»; меню и «Проверка» → `stop`.
- `ui/stats/Improvements.tsx` — блок «Что улучшилось», общий для обоих итогов.
  `improvements(before, session, kind)` лежит в `engine/stats/improvements.ts`.
- `ui/stats/WarmupSummary.tsx` — итог «Разминки» в той же сетке, что `SessionSummary`, без кнопок.
- `ui/stats/NoProgress.tsx` — приглашение: показывается, пока в статистике активного режима нет
  ни одной ноты.
- Итог «Последовательностей» становится четырёхколоночным: числа, медленные, улучшения, кнопки.
  На 1280×800 это проверяется скриншотом.

## Risks / Trade-offs

- **[Итог не влезет на 1280×800]** Четыре колонки и 5 строк чисел. → Проверка скриншотом.
  Запасной вариант: улучшения под медленными нотами в одной колонке.
- **[Адаптивность сужает разнообразие]** → Вес не меньше 1, отношение 3 : 1 — константа
  `WEIGHT_SPAN = 2`, её легко подобрать.
- **[Одна нота в обоих ключах]** Строка «C4 — точнее» не говорит, в каком ключе. → Для басового
  ключа подпись «C4 (бас)» — записано в спеке `practice-stats`.
- **[Время «Разминки» ограничено 5 с]** Медленная нота может не успеть, и тогда она попадёт в
  «не успел», а не в «медленные». Это учтено в трудности через долю неудач.

## Migration Plan

- Старая запись `{ hints }` читается: `stats` отсутствует → пустая статистика обоих режимов.
- Откат — revert PR. Старая версия читает `hints` и игнорирует `stats`.
