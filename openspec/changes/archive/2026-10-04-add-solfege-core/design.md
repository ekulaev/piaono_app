# Design

## Context

В приложении четыре режима (`M-STF`), у каждого свой ход упражнения: `engine/sequences/session.ts` («Последовательности» и «Контур»), `engine/rhythm/session.ts`, `engine/staff/exercise.ts` («Разминка»). Общие для всех уже сейчас: статистика (`engine/stats/stats.ts`, счётчики `clean / errors / skips`, таблицы `notes / intervals / figures` с проверкой ключей при чтении), трудность и взвешенный выбор (`weights.ts`), сводка «Прогресса» (`summary.ts`, таблица `MODE_VIEW`), показ нажатых нот, подсказки, клавиатура с запросами сдвига (`useKeyboardFocus`: `low / high / align`). Рисование нот (`ui/staff/staffDrawing.ts`) ставит у ноты только бекар. Прокрутка клавиатуры упирается только в A0 и C8 (`engine/keyboard/layout.ts`, `clampStart`, `isBlocked`), мини-клавиатура переводит курсор в любое место.

Режимы `M-STF` по решению владельца не переводятся на ядро (C-SOL-1, Р-19).

## Goals / Non-Goals

**Goals:**
- Один ход задания для всех режимов сольфеджио: режим даёт только содержание (генератор, проверку, таблицу «клавиша → ответ», диапазон, ключ типа задания, свои настройки).
- Первый режим «Интервалы» целиком на ядре.
- Ноль изменений в поведении четырёх прежних режимов.

**Non-Goals:**
- Универсальный «движок упражнений» для `M-STF`; смешанный режим «вперемешку» (только не мешаем ему: задание знает свой режим).
- Возможности ядра «на вырост»: длинный ответ реализуется и тестируется в `engine/`, хотя первый режим использует только короткий (он нужен гаммам, знакам, транспонированию и записан в спецификации ядра); UI длинного ответа — рисование нескольких оценённых нот — делается вместе с первым режимом, которому он нужен.

## Decisions

**1. Ядро — чистый редьюсер в `engine/solfege/`, режим — объект-описание.**
```
 engine/solfege/
   types.ts      Task { mode, type, answer: NoteAnswer | ValueAnswer, length, range, view }
   session.ts    start / press / skip / next / tick / stop / repeat  (как sequences/session)
   check.ts      checkNote(exact pitch) / checkValue(table, pitch % 12) / evaluateLong
   events.ts     исход задания -> StatEvent { kind: 'task', key: type }
 engine/solfege/intervals/
   intervals.ts  12 интервалов, полутоны, номер ступени
   generate.ts   (вариант, интервал, направление, первая белая нота) в C4..C6, weightedPick
   spell.ts      запись второй ноты: ступень + знак ♯/♭
   keymap.ts     полутоны от «до» -> интервал
   settings.ts   { variant: 'play' | 'name' | 'both', tasks: 1..10, autoAdvance }
```
Режим описывается объектом `SolfegeMode { id, generate(settings, weights, random), autoShift: 'required' | {default}, range? }`. Сессия хранит в каждом задании `mode` — отсюда INV-5 (смешивание) без отдельного кода. Альтернатива — копировать `sequences/session.ts` под режим: дешевле сейчас, но каждый следующий режим снова копирует ход, ради чего ядро и затевалось.

**2. Статистика: четвёртая таблица `tasks`, режим статистики `intervals`.**
`ModeStats` получает `tasks: Record<string, ItemStats>`; `StatKind` — `'task'`. Ключ типа: `play:up:m3`, `name:down:tt` — проверяется при чтении регулярным выражением режима, как сейчас ключи нот. Старые записи без `tasks` читаются пустой таблицей (как `figures` до «Ритма»). `StatsMode` и `readPracticeStats` дополняются `intervals`. Исходы ложатся на существующие счётчики без изменений: «верно сразу» → `clean`, «после ошибок» → `errors`, «пропущено» → `skips`. Трудность и вес — существующие `difficulty` и `weightOf`; медиана времени — по таблице `tasks`. Сводка: в `MODE_VIEW` строка `intervals: { main: 'task', lists: [{ id: 'tasks', kind: 'task' }] }`.

Почему не в существующую таблицу `intervals`: её ключи — ступени 2–8 без качества (`up3`), тритон и «узнай / сыграй» туда не ложатся, а регулярка чтения отвергла бы новые ключи и обнулила режим.

**3. Автопереход и итог — та же механика, не тот же код.** Константа отсчёта `COUNTDOWN_MS` и вид отсчёта переиспользуются; флажок на панели — существующий `modeControl` в `App.tsx`, условие расширяется на `intervals`. Сам ход («Далее», «Повторить», «Новая») реализован в `engine/solfege/session.ts`: «Последовательности» не трогаем.

**4. Клавиатура: запрос сдвига с выравниванием `right` и границы прокрутки.**
`KeyboardFocus.align` получает значение `'right'` (нота — крайняя справа). Новое необязательное свойство клавиатуры `bounds: { low, high } | null`: `clampStart` и `isBlocked` учитывают его вместо A0/C8; мини-клавиатура получает те же границы и зажимает курсор. `bounds` задаёт только `App.tsx`, когда активен режим сольфеджио с диапазоном; для прежних режимов `null` — поведение прежнее (тесты `layout.test.ts` на `null`).

**5. Знаки у ноты.** `StaffNote` получает необязательный `accidental: '#' | 'b' | null` рядом с `natural`; `drawNote` и рисование нескольких нот добавляют `Accidental` VexFlow. Размер знака — по умолчанию VexFlow при нашем масштабе нот, он не мельче головки.

**6. Стан задания.** «Сыграй»: одна целая нота (как в «Разминке», без движения). «Узнай»: две целые ноты рядом — рисование нескольких нот уже есть в `sequenceDrawing.ts`; общая функция выносится в `ui/staff/`, если это не меняет «Последовательности» (иначе — отдельная небольшая функция в `ui/solfege/`). Формулировка и «✗ м3» — текст над станом в той же зоне, фиксированной высоты: вёрстка не прыгает.

**7. Легенда.** Полоса фиксированной высоты между станом и мини-клавиатурой, только пока задание с ответом-значением; подписи стоят над клавишами по геометрии клавиатуры (та же, что у подписей `C-KBD-3`). Чтобы стан не прыгал, полоса резервируется на всё время сессии «Интервалов», а не только на заданиях «Узнай». Ряд «клавиша — значение» на компактном экране перенесён в `C-APP-5` (компактного экрана ещё нет); до него на низком окне полоса легенды скрыта.

**8. Настройки и меню.** `ModeId` += `'intervals'`; `MODES` — пятым. `ModeSettings` += `IntervalsSettings`; чтение с дефолтами по образцу `sequences/settings.ts`. Форма — `ChoiceGroup`, `Stepper`, `Toggle` из `ui/controls`.

**9. Переводы.** Новые ключи `interval.quality.*` (полные, ru/en), `interval.short.*` (м3 / m3, тр / TT), `solfege.*` (формулировки, «Какой интервал?», итог, приглашение, подсказка с таблицами). Старые `interval.name.*` не трогаем.

## Risks / Trade-offs

- **Правка общих мест рядом с ежедневными режимами** (статистика, клавиатура, меню). → Все новые ветки включаются только для `intervals`; тесты: старая запись `progress.v1` читается без потерь, `bounds = null` даёт прежние `clampStart`/`isBlocked`, «Последовательности» центрируют как раньше.
- **Высота полосы легенды** может съесть место у стана на планшете 1280×720. → Проверка в Playwright на 1280×800 и 1280×720; при нехватке легенда уменьшает отступы, но не шрифт ниже 18 px.
- **Длинный ответ без UI в первом change** — часть ядра проверяется только тестами. → Принято: UI оценки нескольких нот естественно делать с режимом «Гаммы»; спецификация ядра его уже описывает.
- **Энгармонизм в записи второй ноты.** Ошибка в таблице записи даст «странную» ноту на стане. → Полный перебор в тесте: 7 белых нот × 12 интервалов × 2 направления — ступень верна, полутоны верны, знаков не больше одного.
