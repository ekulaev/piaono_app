# Design

## Context

Мотивация — proposal.md → Why. Требования — `specs/staff-exercise`, `specs/connection-status`.

Сейчас:

- `App` превращает события пианино и касания в сыгранные ноты: `reduce()` движка клавиатуры
  возвращает `playedNote`. Сейчас из неё берётся только `lastNoteName` для крупного имени ноты.
- `WaitingScreen` — сетка: индикатор / прокручиваемая середина (подсказки, имя устройства,
  крупное имя ноты) и кнопки / клавиатура.
- VexFlow в зависимостях нет. Workbox кеширует все собранные `js/css/...`, лимит файла
  по умолчанию — 2 МиБ.

## Goals / Non-Goals

**Goals:**

- Логика упражнения (фазы, тайминги, группы нажатий, выбор ноты) — чистые функции от времени,
  проверяемые юнит-тестами без браузера и без реального ожидания.
- Кадр движения не вызывает ни рендер React, ни перерисовку VexFlow.
- Нотный шрифт доступен офлайн.

**Non-Goals:**

- Звук, счёт, статистика, настройки скорости, автопрокрутка клавиатуры к ноте.
- Последовательности нот и режим «без таймера» — этапы 4–5.

## Decisions

### D1. `engine/staff` — автомат упражнения, время передаётся снаружи

```
          start(now)                 tick: now >= startedAt+5000
  idle --------------> moving -----------------------------> pause(until = +500)
   ^                   |  ^ |                                    |
   |  stop(any)        |  | | played(wrong group ends)           | tick: now >= until
   +-------------------+  | +--> moving + wrongUntil = groupEnd+500
                          |                                      |
                          | played(correct)                      v
                          +--> correct(until = now+500) --tick--> pause --> moving (новая нота)
```

- `ExerciseState` = `idle | moving | correct | pause`. У `moving` есть `note { pitch, clef }`,
  `appearedAt`, `wrongUntil | null` и `group { startedAt, hadCorrect } | null`.
- Функции:
  - `start(now, random)`;
  - `stop()`;
  - `played(state, pitch, now)`;
  - `tick(state, now, random)` — сдвигает таймеры;
  - `progress(state, now)` — доля пути 0..1 для отрисовки.
- Группа одновременных нажатий:
  - первое нажатие открывает группу на 50 мс;
  - верная высота в группе сразу даёт `correct`;
  - в `tick`, когда `now ≥ group.startedAt + 50` и верной ноты не было, `wrongUntil`
    становится `group.startedAt + 50 + 500`, а группа закрывается.

  Повторная ошибка продлевает `wrongUntil` тем же правилом.
- Моменты перехода берутся из расписания, а не из «когда пришёл кадр». Например, пауза
  начинается ровно в `appearedAt + 5000`. Поэтому редкие кадры (свёрнутая вкладка) не копят
  ошибку тайминга.
- `random` передаётся параметром (`() => number`), в тестах — детерминированный.

**Альтернатива:** таймеры `setTimeout` внутри UI. Отклонена: логику нельзя проверить без
реального ожидания, а таймеры расходятся с кадрами отрисовки.

### D2. Выбор ноты

`pickNote(random)`:

1. равновероятно выбирается белая клавиша из объединения диапазонов B1–D6;
2. ключ — единственный подходящий, а для G3–F4 — случайный.

Диапазоны — константы рядом с функцией, с комментарием «не больше двух добавочных линий».

### D3. Отрисовка: два SVG-слоя, движение через CSS `transform`

- **Слой стана:** VexFlow `Stave` без ключа рисует 5 линий. Перерисовывается только при смене
  размера. Ключ рисуется отдельной отрисовкой, когда появляется нота (INV-2).
- **Слой ноты:** `StaveNote` (целая, `w`) с добавочными линиями рисуется в отдельный SVG.
  Положение по вертикали вычисляет VexFlow от того же невидимого `Stave` (сам стан в этом слое
  не рисуется). По горизонтали нота рисуется у `x = 0`. Вокруг головки ноты рисуется наше кольцо
  (`<circle>`): сплошное для верной, `stroke-dasharray` для неверной.
- **Движение:** в `requestAnimationFrame` вычисляется `progress(state, now)`, и слою ноты
  задаётся `transform: translateX(...)` через ref. React в кадре не участвует. React
  перерисовывает только при смене фазы: появилась нота, верно/неверно, пауза, стоп. Смена фазы
  определяется в том же `tick`.
- **Толщина линий:** стилем стана и добавочных линий VexFlow задаётся `lineWidth` примерно
  вдвое больше значения по умолчанию, с учётом масштаба. Цвет — `--ink`.
- **Цвета результата:**
  - верная нота — `#1a5216` (контраст с «бумагой» больше 7:1);
  - неверная — `#7a1a10` (≈ 9:1).

  Цвета заводятся токенами в `index.css`, акцент `--accent` не используется.

**Альтернатива:** перерисовывать весь стан VexFlow на каждом кадре. Отклонена: это десятки
SVG-операций и сборка DOM 60 раз в секунду на планшете. Риск по отклику 50 мс.

### D4. Размер стана

`ResizeObserver` на зоне стана. Масштаб VexFlow считается так, чтобы высота диапазона
«2 добавочные линии сверху — 2 снизу» (≈ 10 промежутков между линиями плюс поля под головку
ноты) равнялась высоте зоны. Ширина стана — 90 % ширины зоны. Всё центрируется.

Отдельного правила «не меньше высоты клавиатуры» в коде нет: стан всегда заполняет зону. Если
зона выше клавиатуры, стан больше клавиатуры; если ниже (телефон), стан вписывается в зону.

### D5. Шрифт и офлайн

Импорт `vexflow/bravura`: шрифт Bravura встроен в модуль и регистрируется через `FontFace`,
отдельного сетевого запроса нет. В `vite.config.ts` для Workbox поднимается
`maximumFileSizeToCacheInBytes` до 5 МиБ, чтобы крупный чанк VexFlow попал в precache.
Предупреждение Vite о размере чанка подавляется через `chunkSizeWarningLimit` с комментарием,
почему.

Перед отрисовкой стана ждём загрузки шрифта (`document.fonts.load` / промис готовности
VexFlow). Иначе при первой отрисовке ключ нарисуется запасным шрифтом.

### D6. Встраивание в приложение

- `App` держит упражнение (`useExercise`):
  - каждый `playedNote` из `handleKeyInput` передаётся в `exercise.played(pitch)`;
  - `setScreen('check')` сначала вызывает `exercise.stop()`;
  - состояние связи на упражнение не влияет.
- `lastNoteName` и крупное имя ноты удаляются из `App` и `WaitingScreen`.
- Раскладка `WaitingScreen`: `auto` (индикатор) / `auto` (подсказка, `overflow-y: auto`,
  `max-height`) / `minmax(0, 1fr)` (стан) / `auto` (кнопки) / зона клавиатуры. Кнопка
  «Старт/Стоп» — `button--primary`, сразу справа от «Проверки пианино».
- Приглашение в состоянии «на связи»: «Нажми „Старт“».

### D7. Тесты

- `engine/staff/*.test.ts` — все сценарии `staff-exercise`, для которых не нужен экран
  (тайминги, группы, диапазоны, паузы, стоп), с явными значениями `now`.
- Headless Chromium:
  - раскладка на 1280×800 и 740×360;
  - старт/стоп;
  - замер времени проезда ноты (±100 мс) и паузы (±50 мс) через `performance.now`
    в странице;
  - верное и неверное нажатие касанием;
  - оттенки серого для колец;
  - офлайн-проверка через `context.setOffline`.

## Risks / Trade-offs

- **[Вес VexFlow с Bravura, примерно 1–1,5 МБ]** → Один раз при установке, дальше из кеша.
  Замер размера чанка — в задачах. Если окажется больше 5 МиБ, лимит пересматривается.
- **[Внутренний API VexFlow для отрисовки ноты без стана]** → Используется только публичный
  API (`Stave`, `StaveNote`, `TickContext`, `setContext`, `draw`). При проблеме — запасной
  путь: рисовать слой ноты вместе с прозрачным станом.
- **[Ноты вне видимой части клавиатуры (~1,3 октавы)]** → Вне scope по C-STF-1. На пианино
  не мешает. Отмечено в чек-листе PR.
- **[Движущийся объект хуже читается при слабом зрении]** → Это решение владельца (C-STF-1).
  Нота крупная и контрастная, движение равномерное, без рывков.
