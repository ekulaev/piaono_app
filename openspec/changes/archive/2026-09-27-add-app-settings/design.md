# Design

## Context

Мотивация — proposal.md. Требования — `specs/app-settings` и изменения остальных capability.

Что есть:

- **Экраны.** `App` хранит `screen: 'waiting' | 'check'` и рендерит один из двух.
  - `WaitingScreen` сам рисует `ConnectionStatus`, подсказку `Hint`, имя устройства и кнопки
    «Проверка пианино», «Попробовать снова», «Перезапустить», «Обновить сейчас».
  - `CheckScreen` рисует свой `ConnectionStatus`, список устройств, глиссандо, «Переподключить
    пианино», ошибку системы и журнал.
- **Раскладка главного экрана** — сетка `.waiting` с областями `status / message / staff /
  actions+control`; на низком экране (`max-height: 30rem`) — `status+control / actions / staff`.
  Клавиатура — нижний ряд `.waiting-screen`: `max(25svh, 8rem)`.
- **Переподключение.** «Попробовать снова» зовёт `monitor.retry()` без перезагрузки; «Перезапустить»
  и «Переподключить пианино» — `window.location.reload()`.
- **Обновление** — `useAppUpdate()`: `updateReady`, `applyUpdate`.
- **Меню режимов** — `position: fixed; top: 0; bottom: 0` справа, подложка на весь экран.
- **Версии нет:** `package.json` — `0.0.0`, в сборку ничего не подставляется.

## Goals / Non-Goals

**Goals:**

- Одна верхняя панель над всеми экранами — один и тот же элемент, не пересоздаётся при переходах.
- Главный экран — только стан, кнопки и клавиатура.
- Всё про пианино и приложение — в «Настройках»; «Проверка пианино» — вложенный экран.

**Non-Goals:**

- Экран «Прогресс», значок «Прогресс» и диалог «Да / Нет» — 8б.
- Элемент «Подсказка» — 8в.
- Изменения слоя `midi/` и хранения настроек.

## Decisions

### D1. Экраны и переходы — в `App`

- `screen: 'main' | 'settings' | 'check'`.
- `openSettings()` — `stopExercises()` и `menu` закрыто, затем `settings`. Сюда ведут кнопка
  «Настройки» и статус в панели. На экране `settings` кнопка ничего не делает.
- `goHome()` — `main`; «Назад» в «Проверке» — `settings`.
- Разметка:

  ```
  <div class="app">          grid-rows: 4rem minmax(0, 1fr)
    <TopBar .../>            одна на все экраны
    {main | settings | check}
  </div>
  ```

**Альтернатива:** панель внутри каждого экрана. Отклонена: панель пересоздавалась бы при каждом
переходе, её высота и положение могли бы разъехаться.

### D2. Верхняя панель — `ui/topbar/TopBar.tsx`

- Строка на всю ширину, высота — ряд `.app`: `4rem` (72 px при базовом шрифте 18 px), на низком экране
  (`max-height: 30rem`) `3.5rem`, как был сжатый блок статуса — иначе стану на телефоне не хватает места; внутренний блок `width: min(80%, 100% - 2rem)`, на узком
  экране (`max-width: 37.5rem`) — вся ширина с полями `1rem`.
- **Статус** — `<button>`: значок из `ConnectionStatus` (те же классы `status--<state>` и формы)
  и текст состояния, до двух строк (`line-clamp` не нужен: тексты короткие). Подпись для диктора —
  «<состояние>. Открыть настройки»; объявление смены — `aria-live="polite"` на тексте, как сейчас.
- **Справа:**
  - «Обновить» — ячейка фиксированной ширины всегда в разметке; без обновления кнопка скрыта
    (`visibility: hidden`), место остаётся;
  - «Настройки» — на своём экране `aria-current="page"`.
- **Подписи** значков — `<span class="topbar__label">`, скрыты при `max-width: 56.25rem` (900 px);
  у кнопки всегда `aria-label` и `title`.
- `z-index` панели ниже подложки меню режимов: касание панели при открытом меню закрывает меню.

### D3. Значки — встроенный SVG, `ui/icons/`

- Шестерёнка, круговая стрелка, домик — по одному компоненту.
- `viewBox 0 0 24 24`, `stroke: currentColor`, толщина линии 2.5, размер `2rem`: не «волосяные»
  линии (CLAUDE.md §6).
- Без зависимостей и шрифтов значков.
- Класс `.line-icon` (без заливки): имя `.icon` уже занято залитым значком «Переключать автоматически».

### D4. Статус и подсказки — `ui/ConnectionStatus.tsx`

- `connectionTexts.ts` — `STATUS_TITLE`, `statusClass` и таблица `CONNECTION_HELP: Record<
  ConnectionState, string | null>` — строки приложения Г C-APP-1 (`null` у `connecting` и
  `connected`).
- `ConnectionStatus.tsx` — только компонент значка `StatusIcon` (линтер: компоненты и константы —
  в разных файлах).
- `Hint` из `WaitingScreen` удаляется; `ConnectionStatus`-блок больше нигде не рисуется.

### D5. Главный экран — `WaitingScreen`

- Убираются `ConnectionStatus`, `.waiting__message`, `Hint`, имя устройства, «Попробовать снова»,
  «Перезапустить», «Обновить сейчас», «Проверка пианино». Пропсы `devices`, `activeDeviceId`,
  `connectionState`, `updateReady`, `onRetry`, `onRestart`, `onOpenCheck`, `onApplyUpdate` уходят.
- Сетка: `staff / actions+control`. На низком экране флажок режима встаёт справа от кнопок.
- **Слот:** без `slotButton` — пустой `<span class="waiting__slot" aria-hidden>` той же ширины
  (`min-width: 13.5em`, высота кнопки): «Старт» и «Режим» не сдвигаются.

### D6. Настройки — `ui/settings/SettingsScreen.tsx`

- Шапка: «Назад» и `<h1>Настройки</h1>`. Ниже — список строк `SettingsRow` с `label`, значением
  справа и необязательной строкой `note` снизу.
- Список — `overflow-y: auto`, сам экран не прокручивается.
- Строки:

  | Строка | Содержимое |
  |---|---|
  | «Пианино» | `StatusIcon` + текст, имя активного входа, «Переподключить» (кроме `unsupported`); `note` — `CONNECTION_HELP[state]` |
  | «Устройство» | только при `devices.length > 1`; кнопки входов с «слушаю» — стили `.device` переезжают из `CheckScreen.css` |
  | «Проверка пианино» | кнопка «Открыть» |
  | «Глиссандо» | `Toggle` из `Controls` |
  | «Версия» | «сборка от ДД.ММ.ГГГГ» и «Обновить», если `updateReady` |

- Фокус при открытии экрана — на «Назад», как в меню режимов: клавиатурой сразу видно, где ты.

### D7. «Переподключить» = перезапуск

- Одна кнопка вызывает `restartApp()` (`location.reload()`); она помогает во всех случаях, включая
  разрешение, выданное после отказа (C-APP-1, Р-4).
- `monitor.retry()` остаётся в слое `midi/` со своими тестами — это часть модуля, а не интерфейса.

### D8. Дата сборки

- `vite.config.ts`: `define: { __BUILD_DATE__: JSON.stringify(new Date().toISOString()) }`.
- Объявление в `src/vite-env.d.ts`.
- Формат `ДД.ММ.ГГГГ` — чистая функция `formatBuildDate` в `ui/settings/` с тестом.
- В тестах и dev-сервере значение тоже есть: vitest берёт тот же конфиг.

### D9. «Проверка пианино»

- Шапка: «Назад» (→ `settings`) и «Домой» (значок домика + подпись, → `main`), `<h1>`.
- Остаются журнал и `accessError`. Список устройств, глиссандо, «Переподключить» и блок статуса
  убираются.

## Risks / Trade-offs

- **[Высота на телефоне]** Панель 4rem постоянна; на 740×360 блок статуса раньше сжимался до 3.5rem.
  → На 360 px высоты стан получает примерно столько же места, сколько раньше: строки подсказки на
  телефоне и так не было. Проверяется headless-снимком 740×360.
- **[Подсказка при проблеме только в настройках]** Ученик на главном экране видит лишь статус в
  панели. → Статус — кнопка прямо в «Настройки»; в 8в появится «?».
- **[Перезагрузка вместо повторного запроса]** Чуть дольше, чем `retry()`. → Оболочка из кеша, а
  перезагрузка — единственный путь, который гарантированно помогает (Chrome запоминает отказ).

## Migration Plan

- Хранение не меняется: `glissando`, `preferredInput` — в `piaono.settings.v1`, как раньше.
- Откат — revert PR.
