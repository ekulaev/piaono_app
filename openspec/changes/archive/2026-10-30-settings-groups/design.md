# Design

## Context

Экран «Настройки» — один компонент `src/ui/settings/SettingsScreen.tsx`: список `<ul>` из
`SettingsRow`, строки показываются по условиям (`compact`, `keyboardShown`, число устройств).
Прокручивается только список (`.settings__list`, `overflow-y: auto`). Экран монтируется заново при
каждом открытии (`screen === 'settings'` в `App.tsx`) и живёт в колонке `.screen` шириной до 60rem.
Шапка — общий `ScreenHeader` («Назад», заголовок, на вложенных экранах «Домой» справа).
Настройки — `storage/settings.ts`, каждое поле читается отдельно с значением по умолчанию.
Требования — `specs/app-settings/spec.md`; мотивация — proposal.md.

## Goals / Non-Goals

**Goals:**
- Разложить существующие строки по трём группам без изменения самих строк и их обработчиков.
- Свёрнутость бара — одно новое поле настроек; маленькие окна — только CSS.

**Non-Goals:**
- Общий компонент «вкладок» для других экранов: пока он нужен одному экрану.
- Правка текстов других capability, где упомянута «строка «Пианино»» (`connection-status`,
  `midi-input`): требование «Строка «Пианино»» говорит, что они относятся к строке «Связь».

## Decisions

**Д-1. Выбранная группа — локальное состояние экрана.** `useState<SettingsGroupId>('piano')`
внутри `SettingsScreen`. Экран монтируется при каждом открытии, поэтому «всегда открывается
„Пианино“» выходит само, без кода сброса; поворот планшета экран не перемонтирует — группа
сохраняется. Альтернатива — состояние в `App.tsx` — пришлось бы сбрасывать вручную.

**Д-2. Описание групп — небольшой список в `ui/settings/groups.ts`.** `SETTINGS_GROUPS`:
`{ id, labelKey, Icon }` для «Пианино», «Клавиатура», «Версия». Бар строится по списку; какие
строки в группе — решает `SettingsScreen` веткой по `id` (строки разные по составу и условиям,
обобщать их в данные — лишняя абстракция). `C-APP-4` добавит четвёртую запись.

**Д-3. Бар — вертикальные вкладки WAI-ARIA.** `role="tablist"` с `aria-orientation="vertical"`,
пункты `role="tab"` с `aria-selected` и `aria-controls`, содержимое `role="tabpanel"` с
`aria-labelledby`. Перемещающийся `tabIndex` (выбранный — 0, остальные — −1); стрелки
вверх/вниз и Home/End переключают группу сразу. Выбранный пункт — заливка `--ink`, текст
`--paper` и толстая рамка, как `.device--active`.

**Д-4. Свёрнутость — поле `settingsBarCollapsed: boolean` в `piaono.settings.v1`.** Читается как
остальные булевы поля: нет поля или не boolean → `false`. Запись через существующий
`updateSettings` в `App.tsx` (читаем — заменяем своё поле — пишем). Новый ключ и миграция не
нужны: формат совместим.

**Д-5. Узкое окно — CSS (дополнено Д-10).** Корень экрана получает класс `settings--collapsed` по
сохранённому значению. Медиазапрос `(max-width: 37.5rem)` (600 px, тот же порог, с которого
строки ставят название над значением) прячет подписи пунктов и кнопку сворачивания независимо
от класса. JS-хук размера окна не нужен, сохранённое значение не трогается.

**Д-10. Узкое окно — выдвижная панель (C-APP-6, Р-15).** Бар остаётся тем же `tablist`, на узком
окне CSS ставит его `position: fixed` справа на всю высоту и прячет, пока панель закрыта; состояние
«панель открыта» — локальный `useState` экрана. Узкое окно в JS узнаём через `matchMedia`
(маленький хук по образцу `useCompactScreen`): от него зависят подпись и значок кнопки в шапке,
закрытие панели при расширении окна и фокус. Подложка и закрытие по клику мимо и Esc — как в
`ModeMenu` (клик, а не pointerdown). Альтернатива — полоса значков под шапкой — отвергнута
владельцем: строки и так получают всю ширину, а приём «панель справа» ученику знаком.

**Д-6. Кнопка сворачивания — в `ScreenHeader` через новый необязательный слот `actions`.** Слот
стоит в конце строки шапки (`margin-left: auto`, как «Домой»). Так шапка остаётся общей, и у
«Настроек» нет своей копии. `aria-expanded` и `aria-controls` указывают на бар; подпись
диктора — «Свернуть список групп» / «Развернуть список групп».

**Д-7. Раскладка — сетка из двух колонок.** Под шапкой `display: grid;
grid-template-columns: minmax(0, 1fr) auto; column-gap: 1.5rem; min-height: 0`. Левая колонка —
подзаголовок и прокручиваемый список строк; правая — бар `overflow-y: auto` (прокрутка
появляется только при переполнении, на 740×360). Ширина бара — по содержимому (`max-content`),
в свёрнутом виде — значок с полями (~4.5rem).

**Д-8. Значки.** В `ui/icons/Icons.tsx` по тем же правилам (24×24, линия 2.5): `PlugIcon`
(штекер с двумя контактами и кабелем), `ScreenKeysIcon` (рамка экрана с тремя клавишами),
`InfoIcon` (круг с «i»), `CollapseIcon` (двойная стрелка; направление задаёт свойство).

**Д-9. Тексты.** Новые ключи в `ru.ts` и `en.ts`: `settings.group.piano` («Пианино» / «Piano»),
`settings.group.keyboard` («Клавиатура» / «Keyboard»), `settings.group.version` («Версия» /
«Version»), `settings.connection` («Связь» / «Connection»), `settings.bar.collapse`,
`settings.bar.expand`, `settings.bar.list` (имя списка для диктора). Ключ `settings.piano`
больше нигде не нужен (строка теперь «Связь») и удаляется. Подзаголовок группы берёт тот же ключ,
что и пункт бара.

## Risks / Trade-offs

- [На 360×740 строкам остаётся около 250 px, «Устройство» с длинными именами и счётчик «− N +»
  могут не поместиться] → проверить скриншотом; строки уже ставят название над значением, кнопки
  устройств переносятся. Запасной вариант — полоса значков под шапкой (C-APP-6, Р-10) — только
  через правку спецификации.
- [Мгновенная смена ширины строк при сворачивании — заметный сдвиг] → это прямое действие ученика,
  не самопроизвольный сдвиг; шапка и бар не двигаются, анимации нет.
- [Касание переключателя рядом с баром] → зазор 1.5rem между колонками.
- [Ширина бара на будущих языках] → правило «одно слово» (INV-2 C-APP-6); ширина по содержимому.

## Migration Plan

Совместимое добавление поля: старые записи читаются, бар развёрнут. Откат — возврат версии;
лишнее поле в записи прежняя версия просто игнорирует (`loadSettings` читает поля поимённо).
