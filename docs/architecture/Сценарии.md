# Сценарии

Как данные идут через слои в главных путях. Подробности поведения — в спецификациях OpenSpec,
названных в каждом сценарии.

## 1. Сыграл ноту → отклик на экране

Бюджет — отклик за ≤ ~50 мс (CLAUDE.md §5). Путь короткий и без ожиданий: ни одного таймера,
сети или записи на диск между нажатием и перерисовкой.

```mermaid
sequenceDiagram
    participant P as Пианино
    participant M as midi/midiAccess
    participant A as ui/App (Main)
    participant K as engine/keyboard
    participant S as Сессия режима (ui-хук + engine)
    participant R as React

    P->>M: MIDI-сообщение (3 байта)
    M->>M: parseMidiMessage → noteOn или null
    M->>A: onNoteEvent(noteOn, время события)
    A->>K: reduce(состояние клавиш, pianoDown)
    K-->>A: новое состояние + сыгранная нота
    A->>S: played(высота или время) — во все сессии
    S->>S: автомат engine: верно / неверно
    A->>R: setState → перерисовка клавиши, стана, полосы нот
```

- Касание экранной клавиатуры входит в тот же `handleKeyInput` (`touchDown` вместо `pianoDown`):
  дальше ноты с пианино и с экрана неотличимы.
- Время — это момент самого события (MIDI `timeStamp` или касания), а не момент обработки:
  «Ритму» нужно точное время удара.
- Нота идёт во все сессии сразу, но меняет состояние только та, что сейчас идёт.
- Последнее состояние клавиш держится в `ref`: события приходят чаще кадров, и ждать рендера нельзя.
- Ошибка в обработчике ноты не обрывает приём следующих (`emitNote` ловит исключения).

Контракт: `midi-input`, `piano-keyboard`, режимы — `staff-exercise`, `sequences-mode`, `rhythm-mode`,
`solfege-tasks`.

## 2. Планшет уснул и проснулся

Связь восстанавливается сама, ученик ничего не нажимает (CLAUDE.md §5).

```mermaid
sequenceDiagram
    participant B as Chrome (Web MIDI)
    participant M as midi/midiAccess
    participant A as ui/App
    participant U as Индикатор связи

    Note over B: планшет уснул, порт пропал
    B->>M: statechange
    M->>M: sync: входов нет, пианино было → lost, зажатые ноты отпущены
    M->>A: onConnectionChange('lost')
    A->>U: «Связь потеряна»
    Note over B: планшет проснулся
    B->>M: statechange (порт снова на связи)
    M->>M: sync: выбор входа (id → имя → первый), подписка
    M->>A: onConnectionChange('connected')
    A->>U: «Пианино на связи»
    B->>M: visibilitychange / focus
    M->>M: reopenActive: закрыть и открыть вход — страховка, если statechange не пришёл
```

- `lost` отличается от `no-device`: пианино было на связи в этой сессии.
- Если доступ к MIDI есть, а система его не дала (пианино держит другое приложение) — состояние
  `unavailable` и тихий повтор запроса каждые 5 с.
- Если Chrome запомнил неудачу запуска MIDI, помогает только перезапуск страницы — кнопка
  переподключения в «Настройках» (`restartApp` в `ui/App.tsx`).

Контракт: `connection-status`, `midi-input`.

## 3. Запись прогресса

```mermaid
sequenceDiagram
    participant E as engine (автомат сессии)
    participant A as ui/App
    participant St as engine/stats
    participant P as storage/progress
    participant L as localStorage

    E-->>A: в состоянии сессии появились события (нота, шаг, попытка, задание)
    A->>St: applyEvents(статистика до сессии, события)
    St-->>A: новая статистика режима
    A->>P: saveModeStats(режим, статистика)
    P->>L: прочитать запись целиком
    P->>L: заменить свою часть, записать
```

- Статистика пишется сразу по ходу сессии, а не в конце: «Стоп» или потеря связи ничего не теряют.
- Статистика до сессии (`before`) берётся при «Старт»; к ней прибавляются события сессии. Так же
  «Что улучшилось» сравнивает сессию с историей до неё.
- Уровни подсказок пишутся, когда закончилась последовательность.
- Статистика сольфеджио пишется в режим заданий сессии, а не в активный режим (`C-SOL-1`, INV-5).
- Запись одной части не стирает другую; ошибка записи молчит (CLAUDE.md §7).

Контракт: `practice-stats`, `interval-hints`, `solfege-tasks`.

## 4. Новая версия приложения

```mermaid
sequenceDiagram
    participant G as GitHub (main)
    participant GP as GitHub Pages
    participant SW as Service worker
    participant A as ui/useAppUpdate
    participant U as Ученик

    G->>GP: слияние → проверки → публикация dist/
    Note over SW: при запуске или возврате приложения на экран (если есть сеть)
    SW->>GP: registration.update()
    GP-->>SW: новая сборка, скачана в фоне
    SW->>A: needRefresh = true
    A->>U: кнопка «Обновить» в верхней панели
    U->>A: нажал «Обновить»
    A->>SW: updateServiceWorker(true) → перезагрузка на новой версии
```

Без нажатия новая версия включится при следующем запуске. Сама страница не перезагружается
никогда. Контракт: `pwa-shell`.

## 5. Резервная копия: сохранить и вернуть

```mermaid
sequenceDiagram
    participant U as Ученик
    participant G as ui/settings/BackupGroup
    participant B as storage/backup
    participant L as localStorage
    participant A as ui/App

    U->>G: «Сохранить копию»
    G->>B: createBackup(сейчас)
    B->>L: прочитать настройки и прогресс
    B-->>G: имя файла с датой, JSON
    G->>U: скачать или «Поделиться»
    U->>G: «Вернуть из файла», выбрал файл
    G->>B: readBackup(текст): метка приложения, версия формата, дата
    G->>U: «Да / Нет»
    U->>G: «Да»
    G->>A: onRestoreBackup(копия)
    A->>B: restoreBackup: прогресс, затем настройки, при сбое прогресс возвращается
    A->>A: Main пересоздаётся (новый key) и читает всё заново, включая связь с пианино
```

Контракт: `progress-backup`.
